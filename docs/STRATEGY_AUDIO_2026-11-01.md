## 1. Факты о текущем состоянии (инвентаризация)

**Что есть сейчас в коде (рабочая копия, НЕ на GitHub):**
- `i2s.c/h` — полноценный I2S0-слой: ring в `.ring_buf` (65536 пар, uncached 0x4A400000),
  индексы WR/RD/SYNC в **SRAM A1 (0x98/0x9C/0xA0)**, почты `.coherent`,
  **CPU2 уже запускается** как аудио-ядро (`cpu2_audio_entry` → `i2s_poll_fill`),
  DC-блокер, backpressure (`i2s_ring_wait`), тест-тоны `i2s_test_tone*`.
- Все host-слои (19 систем) зовут `i2s_push_sample/block`; у каждой — свой
  ресемплер (44100/31440/32040/187500 → 48000) с ручной фазой 16.16.
- `emu.c` — throttle + адаптивный target кольца + диагностика.
- 27 файлов изменены относительно GitHub (`e4b5a8b`), есть хвосты:
  - `gba_rs_phase`/ресемплеры завязаны на static в хостах;
  - у SNES был «двойной трек» (вернули к GitHub-состоянию — работаю над этим);
  - GBA: `np=0` (застревание ресемплера) — уже пофикшено в рабочей копии;
  - у части хостов (Atari 8-bit, portfolio) звук вообще no-op.

**Ключевые ограничения железа (доказанные на стенде):**
- **CPU2→core0 через DRAM (.coherent) НЕ работает** (лог r928: CPU2 снял sync,
  core0 не увидел). Работает только SRAM A1 (двунаправленно).
- I2S0 live: `free_50ms=128` → тракт играет ровно, PLL 24.571 МГц.
- CPU2 крутится в вечном цикле без `wfi` (нет источника пробуждения).

**Свежие эталоны (emulator-refs/, git-клоны):**
- `gpsp_fresh` (GBA), `snes9x2005` (SNES), `race` (NGP), `advanceos` — готовы.
- Остальные ядра (fceumm, gpgx, fuse, pce_fast, lynx, mcume, a5200, a7800, atari800,
  gameboy, gearcoleco, msx, bk, vecx, cps1, ms1504, portfolio) — свежие порты
  ТРЕБУЕТСЯ скачать (перечень в §5).

## 2. Стратегия: почему «отдельное ядро» — правильно, и как именно

### 2.1. Роли (жёсткое разделение)

| Ядро | Роль | Отвечает за |
|---|---|---|
| **core0** | UI/Main, **Producer**, синтез | меню, ввод, эмуляция, генерация сэмплов (тест-тон/ядро), запись в ring |
| **CPU2** | **Consumer**, аудио-движок | только I2S0: чтение ring → TX FIFO (guard TXE_CNT); НИКАКОГО синтеза/логики ядер |
| CPU1 | TFT | как сейчас (не трогаем) |

Принципы:
1. **core0 не касается регистров I2S.** Ни одного MMIO-обращения к I2S0 с core0.
2. **CPU2 не синтезирует.** Только перенос `ring→FIFO`. Никаких `printf`/`malloc` в цикле.
3. Связь — **только через память**: данные ring + индексы. Индексы в SRAM A1
   (доказано рабочим), данные — uncached DRAM (.ring_buf, uncached-секция 0x4A4x).
4. **Один производитель, один потребитель** → без мьютексов/спинлоков, только
   release/acquire-барьеры вокруг индексов (`dsb` перед публикацией wr).

### 2.2. Почему это лучше текущего состояния

- Всё, что сегодня в `i2s.c` — уже почти эта схема (CPU2-долив), но:
  - хвосты: backpressure в `i2s_ring_wait` блокирует core0 до 50 мс (фризы);
  - DC-блокер/ресемплеры «размазаны» по хостам;
  - диагностика/логика примешана в горячий путь.
- Целевая схема делает слой **тонким и предсказуемым**:
  - core0: `i2s_audio_push(blk)` — неблокирующая запись (если ring полон — drop счётчик, НЕ ждать);
  - CPU2: цикл «пока FIFO не полон и ring не пуст — копируй» без задержек >1-2 мкс на итерацию.

### 2.3. Что «нового» по сравнению с текущим кодом

| Аспект | Сейчас | Цель |
|---|---|---|
| Индексы | SRAM A1 0x98/0x9C/0xA0 | SRAM A1 (оставить, работает) |
| Данные | .ring_buf uncached | .ring_buf uncached (оставить) |
| Producer backpressure | busy-wait до 50 мс | **неблокирующий** push + drop-счётчик |
| Consumer | CPU2 loop с NOP | CPU2 loop (без wfi), только copy |
| Ресемплеры | в каждом хосте | вынести в единый слой (одна фаза 16.16 на хост, таблица переходов) |
| Тест-тон | i2s_test_tone + i2s_test_tone_freq | один генератор на core0, таблица частот, плавный fade |
| Диагностика | printf в hot path (убираем), счётчики | счётчики в .coherent/SRAM, печать только по запросу |

## 3. Требования к звуку (приёмка)

1. **Тест-тон в меню**: 440 / 1000 / 4000 Гц — чистый синус, без щелчков на
   старте/остановке/смене частоты (fade 5–10 мс).
2. **Никакого постоянного фона/гула/тишины** в паузе (DC-блокер в CPU2, но не
   режущий спектр).
3. **Темп**: ровный, без ускорения/замедления (throttle по wall-clock, не по кольцу).
4. **Нет «двойного трека», «эха», «рекурсии»** ни в одной системе.
5. **Per-система**: правильный ресемплер (не портящий питч/стерео), правильный
   регион (PAL 50 / NTSC 60).
6. Сборка из свежего клона (правило GitHub: `git clone . /tmp/x && make clean && make`).

## 4. Архитектурное решение (черновик — уточняется)

### 4.1. Слой вывода (новый, единственный)

```
core0                                    CPU2
  host_audio_*.c (ресемплер, моно/стерео)
       │  i2s_audio_push(par)            │
       ▼                                 │
  ┌────────────────────┐                 │
  │ ring .ring_buf     │◄──── индексы ────┤ WR (SRAM) ──── core0
  │ WR/ RD (SRAM A1)   │        RD (SRAM) │
  └────────────────────┘                 ▼
                                 i2s_poll_fill(): ring→TX FIFO (48k, guard)
```

- **API** (core0): `i2s_audio_push(int16 L, int16 R)` неблокирующая;
  `i2s_audio_start()/stop()/freq()` для меню-теста.
- **CPU2-**API: `i2s_poll_fill()` — единственная функция, долив по TXE_CNT.
- **Барьеры**: перед WR ↑ `dsb` (как сейчас); перед RD ↑ `dsb`.
- **Silence**: при пустом ring и `g_audio_active` — CPU2 молчит (аппаратный
  zero-fill FIFO), DC-блокер убирает щелчок/фон.

### 4.2. Синтез тест-тона (core0, не CPU2!)

- Таблица синуса 1024 точки (или 256, как в i2s.c сейчас).
- step = freq * TABLE / 48000.
- При «Стоп»/смене частоты — fade-out 8 мс (линейный) перед тишиной.
- Это изолирует: CPU2 просто играет то, что в ring; если тон правильный в
  меню — архитектура работает независимо от ядер.

### 4.3. Что НЕ делать (уроки хвостов)

- НЕ возвращать silence-fill в FIFO (r936-баг: тишина смешивалась с данными).
- НЕ блокировать core0 на полном ring (busy-wait 50 мс — фризы).
- НЕ крутить `wfi` на CPU2 (нет пробуждения — вечный sleep).
- НЕ звать `printf` из CPU2-цикла.
- НЕ полагаться на DRAM-видимость CPU2→core0 — только SRAM A1 (доказано).

## 8. Итоговая рекомендация

Отдельное ядро (CPU2) — **правильно** и уже частично реализовано: CPU2-цикл,
SRAM-индексы и guard TXE_CNT доказаны на железе. Ошибки были не в архитектуре
«ядро отдельно», а в **хвостах вокруг неё**: backpressure-frif, ресемплеры в
хостах, silence-fill, частота запуска ядер. Поэтому стратегия: **сохранить
проверенное ядро CPU2, вычистить всё остальное, единый слой + единый
ресемплер, тест-тон как приёмку, дальше системы по одной.**
