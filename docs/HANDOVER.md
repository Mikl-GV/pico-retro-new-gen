## 1. ЧТО ЭТО
Bare-metal мультисистемный эмулятор для Orange Pi Lite (Allwinner H3, Cortex-A7,
512 МБ, без ОС). Один бинарник h3_bare.bin грузится U-Boot/FEL по адресу
0x40000000. HDMI 1024×600 (меню/игры на core0) + SPI TFT на втором ядре CPU1
(справочные экраны, тач — дополнение, НЕ основной путь). ROM — с SD (FAT32),
ввод — USB-клавиатура (OHCI) + Sega-геймпад/кнопочный пад (PCF8574, I2C).
27 систем READY. Есть стенд у владельца; у тебя стенда НЕТ — прогон делает он.

## 4. АРХИТЕКТУРА / КАРТА ПАМЯТИ (r502, проверено)
0x40000000 образ: .text → .rodata → .data → .bss(0x40CE6D80..0x42B986B8,
≈30.7 МБ) → .noinit_fbn (NOLOAD 96 МБ — пул FBNeo, НЕ обнуляется стартом)
→ _gb_heap 24 МБ (0x48B986C0..0x4A3986C0) → _hend 0x4A3986C0
→ .coherent 0x4A400000 (uncached, USB/OHCI) → _menu_arena 0x4F000000
→ ROM_BUF 0x50000000 → EMU_FB 0x5F800000 → HDMI FB 0x5F900000 → стек 0x60000000.
newlib-куча (_sbrk) живёт ПОСЛЕ coherent-окна (0x4A500000..0x4F000000).
НЕ ломать это расположение (актуальные адреса сверять по `nm build/h3_bare.elf`).
Секция .noinit_fbn и её правила — см. Makefile/linker.ld и docs/ARCHITECTURE.md.
Регистр флага «игра активна» — SRAM 0x74; SRAM-почта CPU0↔CPU1 — 0x18..0x8C.

## 5a. АУДИО-ЯДРО CPU2 (Ф0/Ф1, r584/r585) — звук доливает второе ядро

Цель (решение владельца): освободить core0 от обслуживания звука и убрать
зависимость качества от эмуляции. Итог: core0 СИНТЕЗИРУЕТ звук и кладёт его в
кольцо, CPU2 выводит кольцо в TX FIFO с честным темпом 48 кГц независимо от
нагрузки эмуляции.

- **r584 (Ф0):** кольцо I2S (g_ring_l/r, g_ring_wr/rd) перенесено из BSS в
  `.coherent` (uncached). Без этого CPU2 (выключенный MMU) читал бы stale-
  линии write-back кэша core0. Поведение не менялось (один файл, i2s.c).
- **r585 (Ф1):** долив на CPU2.
  - Почта core0↔CPU2 в `.coherent` (g_audio_* + API i2s_audio_*);
  - `audio_core.c` — cpu2_audio_entry(): вечный цикл flush_max(24)+500мкс=48кГц,
    poll_cmd, heartbeat/диагностика в `.coherent` (в UART0 НЕ пишет);
  - `startup.S` — cpu2_entry: свой стек 0x5FC01000, стеки исключений, NEON до
    C-кода, magic 0x13579BDF (как ждёт h3_secondary_start), прыжок в C;
  - `main.c` — h3_cpu_start(2, cpu2_entry) после CPU1;
  - `emu.c` — emu_throttle(): при активном CPU2 — только udelay конца периода
    (синхронизация видео), FIFO не трогает; fallback на старый долив, если
    ядро не поднялось;
  - `i2s.c` — dc_l/dc_r в `.coherent` (оба ядра трогают); i2s_ring_reset через
    почту; тест-тон/клик при активном CPU2 — только закладка в кольцо;
  - `i2s.h`, `Makefile` — API + audio_core.o.
- **UART:** остались на UART0 (PA4/PA5). CPU2 в него НЕ пишет — диагностику
  числами кладёт в `.coherent`, печатает core0 (один писатель, нет драк).
  Отдельный независимый UART (если захотите позже): UART1 на PA6/PA7 или
  UART3 на PA13/PA14 (оба свободны; PA1 занят тачем, поэтому не UART2).

**Проверка на стенде (что смотреть):**
1. Boot-лог: `smp: CPU1 started…`, `smp: CPU2 started (audio core)`.
2. Звук Lynx/GBA — как раньше (чистый, без хрипов), меню-клики и тест-тоны —
   звучат.
3. Тяжёлая сцена (GBA/аркады): звук НЕ «проседает»/не рвётся, когда кадр
   тяжёлый — это главный эффект (раньше долив конкурировал с эмуляцией).
4. UART без «мусора» от CPU2 (если что-то печатает CPU2 — только через core0).
5. Смена игры (выход/вход): нет «доезда» звука предыдущей системы
   (сброс кольца через почту).

**Открыто (отдельная дельта, отказаустойчивость):** мониторинг живости CPU2
на core0 по heartbeat — сейчас fallback только «не стартовал», а не
«завис во время работы».

## 6. NGP (RACE) — ГЛАВНЫЙ РЕЗУЛЬТАТ r502
Симптом был: Sonic/MS2 — белый экран, CPU застревал (PC 0x3F1C9F / 0x28EE7D),
Bust — зависала после старта. Диагностика трейсами показала: спин читает
0x70C3 = 00 и не дожидается. Фиксы (все в h3_bare/cores/ngp/):
1) tlcs900h.cpp, tlcs_execute: исполнение Sub-CPU Z80 (~1 шаг на 2 такта TLCS) —
   без него игры вечно ждут shared-флаги;
2) tlcs900h.cpp, VBlank: ISR-бит 0x70C3 |= 0x01 (mainram[0x30C3] — shared с
   Z80-адресом 0x00C3) — именно этого ждут Sonic/MS2;
3) ngp_host.cpp: тик звуковых чипов каждый кадр (soundOutput → sound_update/
   dac_update), без вывода в I2S;
4) ngp_host.cpp: хвост mainrom заполняется 0xFF; вторая половина ROM кладётся
   в верхний слот (для 2МБ-игр типа Sonic).
Подтверждено на стенде: первые уровни Sonic, Metal Slug 2nd, Bust — без зависаний.
Отложено осознанно: flash-сейвы NGP (writeSaveGameFile — заглушка), вывод звука
в I2S.

## 7. МЕТОДИКА ДИАГНОСТИКИ (когда что-то виснет)
1. Сначала читать лог владельца (ромбрандер → load_rom → init → дальше тишина).
2. Аналитически проверить путь загрузки слоя: host init (guards !rom/size), формат
   ROM (заголовки), маппинг, рендер-буферы, период кадра, ввод.
3. Ставить ВРЕМЕННЫЕ трейсы в UART строго по гипотезе:
   - PC после кадра (кто крутится);
   - «последние N адресов» перед входом в зону зависания;
   - адреса+значения читаемой памяти в зоне зависания;
   - чтения системных портов.
   Всё с лимитом печати (30–60 строк), иначе спам.
4. По трейсу определить: спин в КОДЕ (реальная функция ждёт флаг) или переход в
   ДАННЫЕ (неверный указатель/маппинг). Для TLCS/RACE: смотреть shared-регистры
   (0x70C3 и др.), Z80-исполнение, ISR.
5. Точечная правка → сборка → прогон владельцем → подтверждение.
6. УДАЛИТЬ диагностику, пересобрать, показать чистый лог.
7. Оформить в docs/AUDIT-2026-09-30.md (номер дельты, статус), обновить память.
