## 1. ЧТО ЭТО
Bare-metal мультисистемный эмулятор для Orange Pi Lite (Allwinner H3, Cortex-A7,
512 МБ, без ОС). Один бинарник h3_bare.bin грузится U-Boot/FEL по адресу
0x40000000. HDMI 1024×600 (меню/игры на core0) + SPI TFT на втором ядре CPU1
(справочные экраны, тач — дополнение, НЕ основной путь). ROM — с SD (FAT32),
ввод — USB-клавиатура (OHCI) + Sega-геймпад/кнопочный пад (PCF8574, I2C).
27 систем READY. Есть стенд у владельца; у тебя стенда НЕТ — прогон делает он.

## 4. АРХИТЕКТУРА / КАРТА ПАМЯТИ (актуально r776, адреса из `nm build/h3_bare.elf`)
0x40000000 образ: .text → .rodata → .ARM.extab/.exidx → .data → .bss
(0x40D05300..0x42BD3748, ≈30.9 МБ) → .noinit_fbn (NOLOAD 96 МБ — пул FBNeo,
НЕ обнуляется стартом) → _gb_heap 24 МБ (0x48BD3760..0x4A3D3760) → _hend 0x4A3D3760
→ .coherent 0x4A400000 (uncached, USB/OHCI + кольцо/почта аудио + L1-таблица
0x4A40C000) → _menu_arena 0x4F000000
→ ROM_BUF 0x50000000 → EMU_FB 0x5F800000 → HDMI FB 0x5F900000 → стек 0x60000000.
newlib-куча (_sbrk) живёт ПОСЛЕ coherent-окна (0x4A500000..0x4F000000).
НЕ ломать это расположение (актуальные адреса сверять по `nm build/h3_bare.elf`).
Секция .noinit_fbn и её правила — см. Makefile/linker.ld и docs/ARCHITECTURE.md.
Регистр флага «игра активна» — SRAM 0x74; SRAM-почта CPU0↔CPU1 — 0x18..0x8C;
диaг-блок исключений — 0x880..0x8A8.

## 5a. АУДИО-ЯДРО CPU2 (Ф0/Ф1, r584/r585) — звук доливает второе ядро

Цель (решение владельца): освободить core0 от обслуживания звука и убрать
зависимость качества от эмуляции. Итог: core0 СИНТЕЗИРУЕТ звук и кладёт его в
кольцо, CPU2 выводит кольцо в TX FIFO с честным темпом 48 кГц независимо от
нагрузки эмуляции.

- **r584 (Ф0):** кольцо I2S (g_ring_l/r, g_ring_wr/rd) перенесено из BSS в
  `.coherent` (uncached). Без этого CPU2 (выключенный MMU) читал бы stale-
  линии write-back кэша core0. Поведение не менялось (один файл, i2s.c).
- **r585 (Ф1):** долив на CPU2.
  - Почта core0↔CPU2 в `.coherent` (g_audio_* + API i2s_audio_*);
  - `audio_core.c` — cpu2_audio_entry(): вечный цикл flush_max(24)+500мкс=48кГц,
    poll_cmd, heartbeat/диагностика в `.coherent` (в UART0 НЕ пишет);
  - `startup.S` — cpu2_entry: свой стек 0x5FC01000, стеки исключений, NEON до
    C-кода, magic 0x13579BDF (как ждёт h3_secondary_start), прыжок в C;
  - `main.c` — h3_cpu_start(2, cpu2_entry) после CPU1;
  - `emu.c` — emu_throttle(): при активном CPU2 — только udelay конца периода
    (синхронизация видео), FIFO не трогает; fallback на старый долив, если
    ядро не поднялось;
  - `i2s.c` — dc_l/dc_r в `.coherent` (оба ядра трогают); i2s_ring_reset через
    почту; тест-тон/клик при активном CPU2 — только закладка в кольцо;
  - `i2s.h`, `Makefile` — API + audio_core.o.
- **r588 (TEMP):** темп долива задаёт АППАРАТНЫЙ TX FIFO, а не таймер —
  `i2s_flush_max` пишет, пока FIFO не полон (TXE_CNT<8), и возвращается, как
  только контроллер освободил место (сам играет ровно 48 кГц). Т.е. CPU2 не
  зависит от `h3_hs_timer_lo_us()` на ядре с выключенным MMU.
- **r700 (D-audio, C1–C3, системный аудит):**
  - **C1** — снят горячий спин CPU2 на `I2S_FIFO_STA`: `i2s_flush_max` теперь
    возвращает число записанных пар; если за проход записано 0 (FIFO на
    границе) — NOP-backoff вместо бесконечного чтения регистра периферии в
    цикле. Разгружает шину для core0/CPU1.
  - **C2** — убран конкурентный `i2s_ring_trim` с CPU2 (data-race на
    `g_ring_rd`/`dc`); срез/сброс DC делает ТОЛЬКО продюсер (`i2s_push_sample`,
    drop-on-high до `AUDIO_RING_TRIM_TARGET`); `i2s_ring_trim` переписан через
    LDREX/STREX.
  - **C3** — spin-ожидания в `i2s_audio_cmd` (PAUSE/RING_RESET) получили
    NOP-backoff; + `dmb sy` перед `g_ring_rd++` в `flush_max` (SPSC-упорядочивание).
  - Файлы: `cores/i2s.c`, `cores/i2s.h`, `cores/audio_core.c`.
- **r702 (итог: N1-почта + C5 + W, подтверждён на стенде):**
  - **N1** — почта core0↔CPU2 на cmd+ack+seq (убрала гонку двухшаговой почты) +
    фикс порядка публикации cmd→dmb→seq (раньше seq первым → CPU2 мог
    подтвердить команду без её исполнения → «зависший RING_RESET/PAUSE»).
  - **C5** — throttle по реальному времени с накоплением «долга» переработки
    (`emu_debt`), сдвиг `emu_ts0` на +period вместо now, `emu_ts0=0;` → reset.
  - **W (watermark)** — анти-«тишина между пачками»: CPU2 не играет, пока кольцо
    не накопит CEILING (~50 мс), и не проседает ниже FLOOR (~19 мс). Убирает
    кадровый тон/гул от стыка «0 → резкий старт» между кадровыми пачками ядер
    (было в `flush_max`: fade в 0 при пустом кольце). `g_ring_watermark_active`
    в `.coherent`, сброс при RING_RESET. Файл: `i2s.c`.
  - **Спам-отладка снята** — убран `printf THR:...` раз в 60 кадров (emu.c),
    диагностика `diag_underrun`/`set_ring`/`set_pairs` в audio_core.c (оставлен
    только heartbeat).
  - **Подтверждено на стенде:** шум (кадровый тон) практически исчез.
  - **r702 (TEST-LAYER, дельта незакрыта):** добавлен тестовый «эмулятор»
    звука — тон пачками за кадр через ШТАТНЫЙ путь кольцо→CPU2→FIFO (без
    паузы CPU2, без прямого доступа к TX FIFO). Размер пачки как у реальных
    ядер: GBA ~549/кадр, Lynx ~640/кадр, крупная ~2400. Пункты в Settings:
    «Layer test: tone GBA (549/fr)», «... Lynx (640/fr)», «... big (2400/fr)».
    Цель: на непрерывном ровном тоне слышно, рвётся ли слой при кадровом
    пачечном производстве (паузы/тон/гул/клики). Файлы: i2s.c (ф-ция
    i2s_tone_burst_test), i2s.h, settings.c.
  - **r702 (FIFO-GONKA, критично):** первые прогоны new-тестов дали тишину
    (старые тест-тон/клик «отлично», т.к. идут НАПРЯМУЮ в TX FIFO мимо
    кольца). Найдена корневая гонка: `i2s_ring_reset()` писал в аппаратный
    TX FIFO (I2S_FIFO_CTL bit25, I2S_TX_CNT) КОНКУРЕНТНО с CPU2-доливом →
    контроллер мог остаться в нерабочем состоянии → тишина/рваный старт.
    Это же глушило РЕАЛЬНЫЕ эмуляторы (входят через emu_prepare→ring_reset
    при живом CPU2). Фикс: `i2s_ring_reset()` теперь ставит CPU2 на PAUSE →
    сбрасывает кольцо/FIFO на core0 → НЕ делает auto-RESUME (тон/клик,
    пишущие в FIFO напрямую, держат CPU2 в паузе); `emu_prepare` и тест
    возвращают RESUME явно. Watermark смягчён (CEILING 1000/FLOOR 250).
    Тест переведён на сбалансированные пачки (800/1600/3200, 60 Гц).
  - **r702 (SCROLL):** вертикальный скролл в Settings — 15 пунктов больше не
    залезают на футер. `settings_draw(sel,scroll)`, SET_VISIBLE=12, индикаторы
    ^/v. Файл: settings.c.
- **UART:** остались на UART0 (PA4/PA5). CPU2 в него НЕ пишет — диагностику
  числами кладёт в `.coherent`, печатает core0 (один писатель, нет драк).
  Отдельный независимый UART (если захотите позже): UART1 на PA6/PA7 или
  UART3 на PA13/PA14 (оба свободны; PA1 занят тачем, поэтому не UART2).

**Проверка на стенде (что смотреть):**
1. Boot-лог: `smp: CPU1 started…`, `smp: CPU2 started (audio core)`.
2. Звук Lynx/GBA — как раньше (чистый, без хрипов), меню-клики и тест-тоны —
   звучат.
3. Тяжёлая сцена (GBA/аркады): звук НЕ «проседает»/не рвётся, когда кадр
   тяжёлый — это главный эффект (раньше долив конкурировал с эмуляцией).
4. UART без «мусора» от CPU2 (если что-то печатает CPU2 — только через core0).
5. Смена игры (выход/вход): нет «доезда» звука предыдущей системы
   (сброс кольца через почту).

**Открыто (отдельная дельта, отказаустойчивость):** мониторинг живости CPU2
на core0 по heartbeat — сейчас fallback только «не стартовал», а не
«завис во время работы».

## 6. NGP (RACE) — ГЛАВНЫЙ РЕЗУЛЬТАТ r502
Симптом был: Sonic/MS2 — белый экран, CPU застревал (PC 0x3F1C9F / 0x28EE7D),
Bust — зависала после старта. Диагностика трейсами показала: спин читает
0x70C3 = 00 и не дожидается. Фиксы (все в h3_bare/cores/ngp/):
1) tlcs900h.cpp, tlcs_execute: исполнение Sub-CPU Z80 (~1 шаг на 2 такта TLCS) —
   без него игры вечно ждут shared-флаги;
2) tlcs900h.cpp, VBlank: ISR-бит 0x70C3 |= 0x01 (mainram[0x30C3] — shared с
   Z80-адресом 0x00C3) — именно этого ждут Sonic/MS2;
3) ngp_host.cpp: тик звуковых чипов каждый кадр (soundOutput → sound_update/
   dac_update), без вывода в I2S;
4) ngp_host.cpp: хвост mainrom заполняется 0xFF; вторая половина ROM кладётся
   в верхний слот (для 2МБ-игр типа Sonic).
Подтверждено на стенде: первые уровни Sonic, Metal Slug 2nd, Bust — без зависаний.
Отложено осознанно: flash-сейвы NGP (writeSaveGameFile — заглушка), вывод звука
в I2S.

## r703 — аудит архитектуры: аудио-кольцо, PA_DAT на CPU2, CS тача на PC4

Пакет правок после архитектурного аудита (Data Abort / карта памяти / гонки).
Безопасные (+ своя аппаратная зона). Сборка чистая (arm-none-eabi 15.2.1 + ucrt64 gcc).

### C1 — hold/fade в .coherent
- `i2s.c`: `hold_l/hold_r/fade_left` были обычными `static` (не в .coherent), хотя их
  писали и core0 (ring_reset/poll_cmd) и CPU2 (flush_max). Запись core0 шла в
  write-back D-cache и не доходила до DRAM → CPU2 при RESUME читал старый пик
  удержания → «треск на старте». Теперь все три — `section(".coherent")` (uncached).
- Файлы: `h3_bare/cores/i2s.c`.

### C2 — атомарный g_ring_rd потребителем
- `i2s.c`: `g_ring_rd++` в `i2s_flush_max` был неатомарным RMW и мог гоняться с
  атомарным `ring_trim_atomic` продюсера (тот двигал тот же индекс LDREX/STREX).
  Откат индекса → перечитывание перезаписанных слотов. Добавлена
  `ring_rd_advance_atomic()` (CAS).
- Файлы: `h3_bare/cores/i2s.c`.

### C4 — liveness CPU2 в emu_throttle
- `emu.c`: раньше проверяли только `i2s_audio_core_active()` («ядро поднялось хоть
  раз»). Если CPU2 зависал в работе (спин на I2S_FIFO_STA) — звук молча исчезал без
  fallback. Теперь в `emu_throttle` отслеживается прирост `i2s_audio_beat()`;
  при «затишье» > 250 мс — fallback на долив core0 (как до Ф1).
- Файлы: `h3_bare/cores/emu.c`.

### PA_DAT → CPU2 (весь рантайм-порт A)
- Решение владельца: освободить регистр PA от межъядерных RMW. core0 и CPU1 больше
  НЕ делают `|=`/`&=` по PA_DAT в рантайме — единственный писатель регистра = CPU2.
- `led.c`: coherent-shadow `g_pa_shadow` (в .coherent) + `pa_dat_request(bit,level)`
  (core0 ставит биты), `pa_dat_apply_desired()` (CPU2 применяет в цикле звука,
  сохраняя не-рантайм биты через `PA_RUNTIME_BITS` = PA10|PA15),
  `pa_dat_set_owner_cpu2(on)` (main после старта CPU2), `pa_dat_apply_if_core0()`
  (до старта CPU2 core0 применяет сам). SD-LED (PA15) и SD-усилка (PA10) — через shadow.
- `i2s.c`: `i2s_mute`, unmute в `push_sample`, `mute_push/pop` (тон/клик, CPU2 в
  паузе → применяется сразу), `i2s_init` (PA10=1 до старта CPU2) — через shadow.
- `audio_core.c`: `pa_dat_apply_desired()` раз в цикле (без прерываний — звук не рвётся).
- `main.c`: `pa_dat_set_owner_cpu2(0)` при старте, `(1)` после `h3_cpu_start(2)`.

### CS тача PA21 → PC4 (спец. ревизия, физическая перепайка)
- Решение владельца: освободить PA из рантайма. `tft_drv.c`: `PIN_CS2 21 (PA21)` →
  `PIN_CS2 4 (PC4)`; `PC_CFG0` добавляет `(1u<<16)` (PC4=GPIO output), `PC_DRV0`
  усиливает PC4; все записи CS тача (cs_select, tft_touch_probe_cs, spi0_init)
  переведены с PA_DAT на PC_DAT. RST дисплея остаётся на PA2 (однократный init).
- **ВНИМАНИЕ:** требуется физическая перепайка CS тача с PA21 на PC4 на плате —
  это зона владельца. Прошивка при ориентировочной старой разводке не увидит тач.

### C3 — double-buffer HDMI (BK/Vectrex), ВЫКЛ. по умолчанию
- Решение владельца: «Выкл. по умолчанию». `emu.c`: `CONFIG_HDMI_DOUBLE_BUF` (0) +
  `emu_hdmi_flip()`, `h3_de2.c`: `h3_de2_set_ui_addr()`. Хуки в `bk_host.c`/`vecx_host.c`
  (no-op при 0). Включение только со стендом — дешёвого vsync-флага у DE2/TCON1 нет.

### C6 — linkcheck в Makefile
- После линковки новый шаг `$(BUILD)/linkcheck.stamp`: (1) в итоговом ELF не должно
  быть неразрешённых символов (bare-metal самодостаточен); (2) blargg-символы
  (Blip_*, Effects_Buffer, Multi_Buffer, Stereo_Buffer, Silent_Blip_Buffer) не должны
  определяться дважды БЕЗ суффикса `_gc` — ловит «тихое» расхождение gc_rename.sh
  (аналог катастрофы r0.193: склейка gc-ссылок с Lynx-blargg → Data Abort в Sms_Apu).
- Файлы: `Makefile`.

## r706 — PA10/PA15 назад на core0 + аппаратный мьют при 0 громкости
Решение владельца (стенд): PA10 (SD-усилка) и PA15 (SD-LED) в рантайме снова
пишет ПОРТ A core0 (откат r703 shadow/CPU2-владельца). Плюс фикс «второго
теста» (Layer) и аппаратный мьют.

### Причина бага (почему игры/Layer молчали, а тоны/клики звучали)
- Тоны/клики в меню: `i2s_mute_push()` применял PA10 через
  `pa_dat_apply_desired()` — НАПРЯМУЮ в регистр, независимо от «владельца CPU2».
- Игры и Layer-тест: `i2s_push_sample()` просил PA10 через `pa_dat_request` +
  `pa_dat_apply_if_core0()`, а при `g_pa_cpu2_owner=1` apply_if_core0 — **no-op**.
- Сценарий: клик в меню → `mute_pop` опускает PA10 в 0 → вход в игру → первый
  push_sample ставит shadow PA10=1, но регистр не трогает (владелец CPU2),
  а CPU2 не применяет (пауза после ring_reset/завис/не стартовал) → усилитель
  на земле навсегда → тишина при ЗАВЕДОМО живом CPU2 (у владельца CPU2
  стартовал и звук тонов был, а эмуляторы — нет).

### Что сделано
- `led.c/h`: удалены coherent-shadow/g_pa_cpu2_owner/pa_dat_request/apply_desired/
  apply_if_core0/set_owner_cpu2. Вместо них одна функция `pa_dat_set(bit,level)`
  — прямая запись PA_DAT с `dsb` (core0). RMW-гонок между ядрами нет: CPU1
  (TFT) PA_DAT не пишет (CS тача на PC4 с r703), CPU2 порт A не трогает.
- `i2s.c`: ВСЕ обращения к PA10 — `pa_dat_set(10,...)`:
  - `i2s_mute(m)` — PA10 = m?0:1;
  - `i2s_init()` — PA10=1 (после старта ядер не зависит от CPU2);
  - `i2s_push_sample()` — при снятии mute PA10=1 (если громкость>0);
  - `i2s_mute_push/pop` — PA10=1/0 (если громкость>0 при push);
  - `i2s_volume(0)` — аппаратный мьют PA10=0; `>0 && !g_muted` — PA10=1;
  - `i2s_tone_burst_test` — при снятии mute PA10=1, плюс fallback-долив
    `i2s_flush_max(24)` на core0, если CPU2 не активен (как C4 в emu_throttle) —
    иначе тон падал бы в кольцо без потребителя.
- `audio_core.c`: убран `pa_dat_apply_desired()` из цикла CPU2 (порт A ему
  больше не нужен).
- `main.c`: убраны `pa_dat_set_owner_cpu2(0/1)`.

### Стенд (что проверить)
1. Меню: клики/тоны 440/1000/3000 — звучат.
2. Игра (Lynx/GBA): звук С ПЕРВОГО кадра, без «тишины до первого нажатия».
3. Settings → Layer test (GBA/Lynx/big): тон идёт через штатный путь
   кольцо→CPU2→FIFO — должен звучать (раньше этот путь молчал).
4. Громкость 0%: тишина ПОЛНОСТЬЮ (PA10=0, усилитель выключен, без фона);
   >0%: звук есть.
5. SD-индикатор PA15 мигает при загрузке ROM (до игры) — не мешает звуку.

## r707 — Layer-тест приведён к схеме эмулятора
- `i2s_tone_burst_test` переведён с ручного `udelay` на `emu_throttle()` (как

## r709–r717 — диагностическая серия (инструменты, не дельты)
- Маркеры стадий/адресов в audio_core/i2s_flush_max, sticky-маркеры A-D/top/
  paused, SRAM-зеркала 0x5000/0x5004, UART-`#` от CPU2. Вывод серии:
  **CPU2 всегда был ЖИВ** (SRAM-зеркала растут синхронно с beat), а `.coherent`
  (DRAM-канал) на чтении core0 отдавал stale — ядра «не видели» друг друга.
  Именно это выдавало «зависший CPU2», растущий ring, молчащий кольцевой тест.
- Побочно r714: сброс флага exc_once (SRAM 0x18) в startup.S — U-Boot оставлял
  мусор, и первый Data Abort тихо уходил в hang без печати F1..F6.

## r722 — ПЕРЕНОС L1-ТАБЛИЦЫ СТРАНИЦ ИЗ ЗОНЫ СТЕКА (критично)
- `startup.S`: U-Boot кладёт TTBR0 в 0x5FFF4000 — в 48 КБ ниже SVC-стека core0
  (0x60000000, растёт ВНИЗ). Глубокие вызовы (printf/fat/загрузка GBA) затирали
  таблицу страниц → MMU деградировал, `.coherent` терял uncached → НЕСТАБИЛЬНОСТЬ:
  зависания на загрузке/в меню/в эмуляторе, случайные краши (стенд: несколько
  перезагрузок, Sonic повис).
- Фикс: в startup.S ДО установки стека копируем L1 (16 КБ) в uncached-хвост
  `.coherent` (0x4A40C000 — после _coherent_end, до кучи), clean+invalidate,
  TTBR0 = новый, TLB invalidate. Стек остаётся на 0x60000000 — теперь безопасен.

## r723 — чистка диагностики
- Удалены ВСЕ маркеры/SRAM-писанина/LT-лог/UART-`#`. Кольцо/почта/audio_core
  чистые (heartbeat остался для liveness C4). SRAM-записи 0x5000/0x5004 из

## r724 — КОРЕНЬ «кольцевой тест молчит / Lynx рваный» + кнопки
- `h3.c` `mmu_mark_uncached`: раньше менял атрибуты (TEX/C/B) у существующей
  записи U-Boot, СОХРАНЯЯ биты базы. Запись для секции .coherent (0x4A400000)
  у U-Boot оказалась мусором (coherent_l1=0xFFF9FFF3 — база 0xFFF00000, не
  0x4A400000!). Итог: core0 мапил .coherent на ФИЗИЧЕСКИЙ 0xFFF00000, а CPU2
  (без MMU) стучал в настоящий 0x4A400000 — ядра в разных физических адресах,
  кольцо/почта мертвы. Теперь дескриптор строится ОТ АДРЕСА (addr & 0xFFF00000),
  AP/domain/XN берутся из валидной секции 0x40000000. На стенде: шумы ушли,
  тишина чистая, есть завалы по частотам (след. дельта — тональная коррекция).
- `emu.c` `emu_esc_hold`: выход из эмулятора — Start + (Mode|X) (Select) —
  работает и на джойстике (Mode=0x800), и на кнопочной плате (X=0x100).
  Клавиатура — ESC как было.

### Стенд r724 (подтверждено владельцем)
- Стабильность восстановлена (ранее «зависает на загрузке/в меню/в эмуляторе»).
- Посторонних шумов нет, где тишина — там тишина. Осталось: завалы по частотам
  (АЧХ/гейн) — отдельная дельта.

## r769 — фиксация адреса DMA-буфера + вынос DEBUG-теста из boot (аудит)
- `linker.ld`: DMA-буфер звука вынесен в ОТДЕЛЬНУЮ секцию `.dma_buf` с жёсткой
  VMA 0x4A410000 — сразу после L1-таблицы страниц (0x4A40C000..0x4A410000,
  startup.S r722). Раньше буфер лежал внутри `.libh3_coherent` через
  `. = ALIGN(64K)` от `_coherent_end` — при уменьшении .coherent-объектов
  сползал вниз, прямо на таблицу страниц (тихая порча MMU/звука).
  Добавлены ASSERT: `_coherent_end <= 0x4A40C000`, `_dma_buf_start == 0x4A410000`,
  `_dma_buf_end == 0x4A420000`.
- `main.c`: удалён DEBUG-вызов `audio_irq_test(8)` из boot (r768) — тон на 8 с
  при каждом включении вместо меню. Тест остаётся в сборке, но не исполняется
  автоматически.
- `main.c`: опечатка в заголовке диалога MSX «YIS-503II» → «YIS-503III».
- `h3_dma.h`: обновлён устаревший комментарий о поллинге CUR_SRC — с r764
  позиция DMA отслеживается по PKG-прерываниям (GIC, CPU2), без поллинга.
- Версия: r768 → r769 (g_fw_version + build:).

## r776 — аудит: чистка мёртвого DMA/GIC-слоя и устранение гонок звука
- УДАЛЕН DMA-путь звука окончательно (JPEG-решение r773): `h3_bare/platform/h3_dma.c`,

- `linker.ld`: секция `.dma_buf` (0x4A410000, r769) удалена вместе с драйвером —
