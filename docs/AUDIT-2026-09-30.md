# Aудит кода — 2026-09-30 (проверено r500)

> **Точка сохранения: версия r500** (нумерация сборок сброшена с r0.4xx → r500,
> 2026-09-30). Все правки сессии r0.417 (Д1..Д28) вошли в r500.

Цель: проверка компиляции, логики, стабильности, карты памяти; реестр ошибок с
фиксацией по мере решения. Решения принимает владелец, правки — малыми дельтами,
по одной проблеме.

## Состояние сборки (проверено чистой сборкой)

- `make clean && make -j$(nproc)` — **OK**, без ошибок.
- `h3_bare.bin` = **13 519 844 байт (~12.9 МБ)**, линковка без undefined.
- Предупреждения: ~75 300 шт., из них ~75 160 — в vendored ядрах (FBNeo cps1/,
  portfolio/cpu.cpp и т.п.), **~139 — в нашем коде**, все одного класса
  `-Warray-bounds` на MMIO-макросах SRAM-почты (`*(volatile uint32_t*)0x78u`):
  **ложные** срабатывания GCC 15 (адреса < 0x1000 трактуются как NULL+offset),
  реальных вылетов за границы не обозначают. Чистятся `-Wno-array-bounds`
  для этих файлов (косметика).
- Единственное реальное формат-предупреждение: `cps1_host.cpp` (`%d` может
  усекаться в snprintf-строку малой длины).

## Карта памяти (проверена по ELF и linker.ld)

```
0x40000000  образ: .text 0x40000000 (7.3 МБ) .rodata 0x4073F0C0 (2.9 МБ)
            .data 0x40A37588 (2.7 МБ) .bss 0x40CE4C00 .. 0x49391D88  (141 МБ!)
_gb_heap    0x49391DA0 .. 0x4AB91DA0  (+24 МБ bump-пул, _hend здесь)
.coherent   0x4AC00000 .. 0x4AD00720  (NOLOAD; объекты OHCI 0x71E, резерв 1 МБ)
_menu_arena 0x4F000000
ROM_BUF     0x50000000 (24 МБ)
EMU_FB      0x5F800000 (320×240×2)
FB_ADDR     0x5F900000 (1024×600×4 = 2.4 МБ, конец 0x5FB58000)
SVC-стек    0x60000000 (растёт вниз; зазор до FB ~4.4 МБ)
```

**Главный факт по памяти: `.bss` = 141 МБ.** Расклад:
- **96 МБ — `pool_mem` в FBNeo** (`burn_memory.cpp:18,31`,
  `CPS1_MEM_POOL_SIZE = 96*1024*1024`, статический массив в BSS);
- ~10 МБ — GPGX `ext`-буфер (`gpgx_core_genesis.o` `ext[0x997ac4]`);
- ~4 МБ — NGP `mainrom`; ~1 МБ — PCE; остальное — обычные глобалы ядер.

Следствия: (1) стартовое обнуление BSS в startup.S пишет ~35 млн слов;
(2) `BurnInitMemoryManager()` делает `memset(pool_mem, 0, 96 МБ)` при КАЖДОМ
входе в аркаду; (3) лимит образа до `_menu_arena` соблюдён с запасом ~65 МБ —
краша нет, но старт/вход в аркады медленные. Оптимизация — отдельным пунктом (см. O1).

## Оптимизация (предложения, не правки)

- **O1. FBNeo pool 96 МБ**: (а) перенести `pool_mem` в NOLOAD-секцию — стартовая
  обнулялка BSS не трогает её, экономим обнуление 96 МБ при старте; (б) убрать
  `memset(pool_mem, 0, 96 МБ)` из `BurnInitMemoryManager` (пул и так инициализируется
  по мере выделения) или обнулять только выданные блоки; (в) рассмотреть
  уменьшение `CPS1_MEM_POOL_SIZE` после замера реального потребления
  (в bprintf есть «pool exhausted»). Эффект: старт быстрее, вход в аркады быстрее.
  **✅ Частично готово (Д25, r0.417)**: (а)+(б) выполнены — `.noinit_fbn`
  NOLOAD-секция в linker.ld, стартовый `memset(pool_mem)` убран; каждый блок
  по-прежнему обнуляется в `_BurnMalloc` (безопасность). BSS: 141 МБ → ~41 МБ.
  (в) — отложено до замера на стенде.
