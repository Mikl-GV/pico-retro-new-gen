# AUDIO REFERENCE — как делать I2S-звук на Allwinner H3 (пособие)

Собрано по рабочей реализации + даташиту H3. Используется для нашего
`h3_bare/cores/i2s.c` (I2S0, 48 кГц, CPU2 доливает TX FIFO из ring).

## 1. Главный референс (рабочий CPU→FIFO на H3)
- `uli/allwinner-bare-metal` — https://github.com/uli/allwinner-bare-metal/blob/jh/audio_i2s.c
  (+ `audio.h`, `ccu.h`). Тот же SoC, CPU (не DMA) наливает TX FIFO по опросу
  `FIFO_STA[23:16]`. Подтверждает: `TX_DRQ` для CPU-долива НЕ нужен.

### Рабочая инициализация (эталонные значения)
```c
I2S_TX0CHSEL = OFFSET_1|CHSEL_2|CHEN_0|CHEN_1;          // 0x00001031
I2S_TX0CHMAP = CH0_SAMPLE(0)|CH1_SAMPLE(1);
I2S_CLKD     = MCLKDIV(1)|BCLKDIV(5)|MCLKO_EN;          // BCLK=/8, MCLKO_EN=бит8 (H3)
I2S_FAT1     = 0;
I2S_FAT0     = SW(3)|SR(3)|LRCK_PERIOD(31);             // 0x1F33
I2S_TXCHCFG  = TX_SLOT_NUM(1)|RX_SLOT_NUM(1);
I2S_FCTL     = TXTL(0x40)|RXTL(0x0f)|TXIM(1)|RXOM(1)|FRX;  // FTX в цикле НЕ трогать
I2S_TXCNT    = 0;
I2S_INT      = TXEI_EN;                                 // бит4; TX_DRQ(бит7) не включать
I2S_CTL      = BCLK_OUT|LRCK_OUT|MODE_SEL(1)|RXEN|TXEN|GEN|SDO0_EN; // 0x00060117
```
Клоки: `PLL_AUDIO_CTRL = 0x80035514` (EN + N=86,M=21,P=4 → 24.571 МГц), ждать
бит28 (LOCK); `I2S_PCM_CLK = 0x80030000` (gate+mux); `BUS_SOFT_RST3` assert→deassert;
`BUS_CLK_GATING2`. `mod_clk` (I2SPCM0_CLK, 0x0B0) должна быть ≈24.576 МГц.

### Рабочий долив
```c
while (((I2S_FSTA >> 16) & 0xff) > 2) {   // [23:16] = сколько СВОБОДНЫХ слов
    I2S_TXFIFO = l;                        // 0x20
    I2S_TXFIFO = r;
}
```

## 2. Регистры (даташит H3, стр. 534/536)
- `I2S0_BASE = 0x01C22000`; `CTL 0x00`, `FMT0 0x04`, `FMT1 0x08`, `ISTA 0x0C`,
  `RXFIFO 0x10`, `FCTL 0x14`, `FSTA 0x18`, `INT 0x1C`, `TXFIFO 0x20`,
  `CLKD 0x24`, `TXCNT 0x28`, `CHCFG 0x30`, `TX0CHSEL 0x34`, `TX0CHMAP 0x44`.
- `FSTA (0x18)`, default `0x10800000`: `[23:16]=TXE_CNT` «Empty Space Word Counter»
  (при пустом = **128** слов = глубина FIFO), `[28]=TXE` (есть место ≥1 слово).
- `FCTL (0x14)`: `FLUSH_TX=бит25`, `FLUSH_RX=бит24` (**R/WAC — самоочищаются**),
  `TXTL=[18:12]` (деф. 0x40), `TXIM=бит2`.
- `INT (0x1C)`: `TX_DRQ_EN=бит7`, `TXEI_EN=бит4`.
- `CLKD (0x24)`: `BCLKDIV=[7:4]`, `MCLKDIV=[3:0]`, `MCLKO_EN` = **бит8** (H3);
  `0` в BCLKDIV/MCLKDIV = **Reserved → нет BCLK → FIFO не сливается**.
- `FMT0 (0x04)`: `SR=[6:4]` (3=16-бит), `SW=[2:0]` (7=32-бит слот),
  `LRCK_PERIOD=[17:8]` (пишется как `period-1`).
- `PLL_AUDIO (CCU 0x008)`, стр.93: `PLL_AUDIO = (24MHz*N)/(M*P)`;
  поля `N=[14:8]`(фактор+1), `M=[4:0]`(фактор+1), `P=[19:16]`(фактор+1),
  `EN=бит31`, `LOCK=бит28`. **24.576 МГц:** `0x80035514` (N=86,M=21,P=4 →24.571).

## 3. Чек-лист bring-up (по симптому «FIFO 128 и не сливается»)
1. Прочитать `FSTA` → `0x10800000`. Если `0` — блок не тактируется/гейт выключен.
2. Записать 4 слова в `TXFIFO` → перечитать `FSTA`: уменьшилось `TXE_CNT` → записи
   доходят (искать дренаж); не изменилось → неверный оффсет/база/гейт
   (ловушка вендорского BSP: `TXFIFO=0x0C` вместо `0x20` для H3).
3. Тактирование: PLL_AUDIO lock; `I2SPCM0_CLK`≈24.576 МГц; `BCLKDIV≠0`,`MCLKDIV≠0`,
   `MCLKO_EN=бит8`; проверить реальную частоту (осциллограф BCLK/LRCK).
4. Включение: `CTL=GEN|TXEN|BCLK_OUT|LRCK_OUT|SDO0_EN`; `0x34` CHEN+CHSEL=2;
   `0x30` TX_SLOT_NUM=1; `FMT0[17:8]=31`.
5. Дренаж: залить 64 слова, перестать писать, за 1 мс `TXE_CNT` должен вырасти
   ~на 96 (≈1 слово/10.4 мкс при 48k). Не выросло — нет такта/включения.
6. Порядок: формат/каналы → flush → TXEN → GEN последним; `FCTL` в цикле не трогать.
7. `TX_DRQ` для CPU-пути не нужен; `TXIM` — только формат данных.

## 4. Вторичные референсы
- U-Boot `drivers/sound/rockchip_i2s.c` — «CPU опрашивает FIFO и наливает» на
  другом железе: `if ((fifolr&0x3f)<0x20) write(txdr)`. Читает УРОВЕНЬ, у нас —
  СВОБОДНОЕ место (не путать семантику).
- `rsta2/circle` `lib/sound/i2ssoundbasedevice.cpp` — паттерн
  producer→очередь чанков→потребитель-устройство; init: выключить→`TXCLR|RXCLR`
  +задержка→каналы→MODE→STBY→EN.
- Linux `sun4i-i2s.c` — `FLUSH_TX=BIT(25)`, `TX_DRQ_EN=BIT(7)`, H3-квирки
  (`MCLKO_EN`=бит8, `LRCK_PERIOD[17:8]`, `mod_clk=24576000`).
- Вендорский BSP `friendlyarm/h3_lichee` `sunxi-i2s0.c` — эталонный порядок
  включения для H3 (и ловушка `TXFIFO=0x0C`).

## 5. Наши найденные ошибки и фиксы
- **PLL_AUDIO (r914, КОРЕНЬ ~73% дропа во ВСЕХ системах):** стояло `N=14,M=14`
  при сохранённом `P=4` → `24*14/(14*4)=6 МГц` (в 4 раза ниже!) → I2S шёл ~12 кГц
  вместо 48 → продюсер переполнял кольцо на ~75%. Фикс: `PLL_AUDIO_CTRL=0x80035514`
  (24.571 МГц). Проверка `PLL_AUDIO=(24MHz*N)/(M*P)`.
- **Громкость (r914):** масштабировалась только PA10 (on/off) → «10%» звучало как
  максимум. Фикс: масштаб сэмплов в `i2s_push_sample` по `g_volume_pct`.
- **CU2 не спит (r914):** при пустом кольце пишем ТИШИНУ в FIFO (~до половины) —
  нет underrun-щелчков/«фантомов» при входе/выходе.
- **FLUSH (r913):** не держать `FLUSH` в `FCTL` — он R/WAC; в цикле долива не трогать.
- **НЕ инициализировать `.coherent` ненулевым значением (r952):** секция NOLOAD,
  `startup.S` её зануляет — инициализатор в память не попадает. На этом уже дважды
  терялись значения (`g_volume_pct`, r904; `s_dc_shift`, r952). Второй случай дал
  «тишину при живом доливе»: `shift=0` → `out = l − lp = l − l = 0`, хотя CPU2
  честно переносил все пары (`fw_delta == wrote`). Для горячих параметров CPU2
  нужен ещё и кламп в рабочем коде (1..30 для `s_dc_shift`).

## 6. Тест-тон: прямой долив FIFO с core0 (r948)

Тест тракта обязан быть детерминированным: он проверяет «I2S0 + усилитель», а не
межъядерный канал. Поэтому тон пишется **напрямую в TX FIFO** из core0, без
кольца и без CPU2.

```c
// 1) CPU2 — на паузу (единственный писатель FIFO на время теста = core0).
i2s_audio_cmd(AUDIO_CMD_PAUSE); SRAM_AUDIO_PAUSED = 1;
// 2) Усилитель принудительно включён, громкость 100 % (после теста вернуть).
// 3) Проверка такта: FIFO должен сливаться (TXE_CNT вернулся к 128 за 50 мс).
// 4) FLUSH_TX только при TX_EN=0 (иначе FIFO клинит), затем TX_EN обратно.
// 5) Долив: пишем пару, только когда в FIFO есть 2 свободных слова.
while (written < total) {
    while (((I2S_FSTA >> 16) & 0xFF) < 2) ;     // ждём место; темп даёт FIFO
    I2S_FIFO_TX = (uint32_t)(uint16_t)l << 16;  // TXIM=0: данные в старших 16 бит
    I2S_FIFO_TX = (uint32_t)(uint16_t)r << 16;
    written++;
}
// 6) Хвост: 64 пары тишины (1.3 мс) → дождаться слива → FLUSH_TX → RESUME.
```

Почему это чисто:
- темп задаёт аппаратный FIFO (128 слов = 64 пары = 1.33 мс при 48 кГц), поэтому
  недоливов нет по построению — в отличие от подачи «пачками по таймеру»;
- один писатель регистра FIFO (CPU2 на паузе) — нет гонки двух ядер на MMIO;
- частота: фаза 32-бит, `step = hz*2^32/48000`, синус по 256-точечной таблице с
  линейной интерполяцией (подавление гармоник лучше −70 дБ);
- код возврата различает отказы: `0` — проигран, `-1` — I2S не готов (init/PLL),
  `-2` — FIFO не сливается (нет такта/блок заперт). Меню показывает это на экране.

Диагностический смысл: если тест молчит при `rc=0`, цифровой тракт отдаёт данные —
искать аналог: PA10 (SD усилителя) не в 1, усилитель, распайка BCLK/LRCK/DIN,
питание модуля. Если `rc=-2` — проверять PLL/делители/гейт (раздел 3, чек-лист).

## 7. Вывод эмуляторов (r949)

Гейт `g_emulators_audio` снят в `i2s_init()` (`i2s_emulators_audio(1)`): host-слои
пишут в SPSC-кольцо, CPU2 доливает TX FIFO. Тест-тон идёт отдельным путём и от
гейта не зависит.

**Lynx (Handy) — эталонный путь, проверенный по коду ядра:**
- `Stereo_Buffer::read_samples()` всегда возвращает `count*2` int16;
  `mix_mono` пишет один и тот же сэмпл в `out[0]` и `out[1]`, `mix_stereo` —
  реальные L/R. Значит `gAudioBufferPointer` = число int16 = `2 × пары`,
  а host читает `p[2i], p[2i+1]` — верно.
- `HANDY_AUDIO_SAMPLE_FREQ = 48000` = частота I2S → ресемпл не нужен.
- blip: `end_frame((gSystemCycleCount - gAudioLastUpdateCycle) / 4)` —
  blip-клок = 16 МГц / 4 = 4 МГц, `set_sample_rate(48000, 60)`.
- кадр 75 Гц → 13333 мкс → ≈640 пар; `emu.c` уточняет период по факту пар.

**Защита продюсера:** в `i2s_ring_wait` 8 подряд таймаутов (CPU2 не выгребает)
переключают на «мягкий» режим — запись только при свободном месте сразу, иначе
дроп. Без этого каждый сэмпл ждал бы 25-50 мс и кадр эмулятора вставал.

**Диагностика:** `LYNX-AUD: ptr=… pairs=… fill=… drop=…` раз в 150 кадров.

### Кто владеет TX FIFO (r951)

| Режим | Пишет в FIFO | Что делает второй участник |
|---|---|---|
| Игра/эмулятор | **только CPU2** (`i2s_poll_fill`) | core0 пишет только в кольцо |
| Тест «Direct» | **только core0** (`i2s_tone_direct`) | CPU2 на паузе (`SRAM_AUDIO_PAUSED=1`) |
| Тест «CPU2» | **только CPU2** | core0 держит кольцо ≤ половины `I2S_RING_MAX_FILL` |

Одновременной записи в FIFO двух ядер нет ни в одном режиме. Второй тест
(`i2s_test_tone_cpu2`) печатает `fw_delta` — сколько пар реально перенесло
аудио-ядро; `fw_delta ≈ wrote` означает, что межъядерный канал живой и виноват
не он.

## 8. Итог r957: рабочая конфигурация (проверено на стенде)

**Звук работает на двух ядрах.** Оба теста в меню валидны:
- Path: Direct (core0 -> FIFO) — FIFO пишет core0, CPU2 на паузе;
- Path: CPU2 (ring -> FIFO) — core0 пишет в кольцо, FIFO доливает CPU2.

Что оказалось решающим (после тонны гипотез):
1. **Данные кольца обязаны быть в SRAM A1** ( x1000/ x3000, 4096 пар). DRAM
   между ядрами ненадёжна в ОБЕ стороны: и CPU2→core0 (r928), и core0→CPU2
   (r957 — внешне корректные счётчики, но рваный/хрипящий звук). Индексы, флаги
   и сэмплы теперь в одном месте — некэшируемой SRAM.
2. **Готовность I2S проверяется по SRAM** ( x94), а не по g_i2s_ready в
   .coherent: иначе CPU2 молча выходит из i2s_poll_fill и кольцо стоит при
   живом eat.
3. **.coherent нельзя инициализировать ненулевым** (NOLOAD + zero-init):
   s_dc_shift терял = 6 → ФВЧ с shift=0 выдавал нули.
4. **Тест-тон не должен зависеть от кольца/CPU2**: прямой долив FIFO по
   TXE_CNT даёт эталон «тракт жив», с которым сравнивается путь через CPU2.
5. **Диагностика не должна работать в потоке**: любой printf в кадре
   блокирует UART и сам опустошает кольцо; сводки печатаются на выходе.

Итоговая скорость/формат: BCLK 3.071 МГц, LRCK 47 991 Гц (PLL 24.571 МГц),
16-бит данные в 32-бит слоте (SR=3, WSS=7), FIFO 128 слов, кольцо 4096 пар.
6. **NES (FCEUmm): канальные громкости = 0 после инициализации.** FCEUI_Initialize()
   обнуляет FSettings и ставит только SoundVolume/ExpVolume; SquareVolume[2],
   TriangleVolume, NoiseVolume, PCMVolume остаются нулями, а микшер умножает
   каждый канал на Volume/256 → APU тикает и отдаёт сэмплы (798/кадр), но они
   нулевые. В libretro это заполняет фронтенд (256). В bare-metal ставим явно.
   Симптом на стенде: NES-AUD: ssize_avg=798 peak=0 nonzero=0.
