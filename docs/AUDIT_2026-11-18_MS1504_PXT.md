> прежний реестр — `docs/AUDIT_MS1504_PXT.md` (r1469..r1484).

## 2. Находки (детали)

### К1 [BUG] pxt: `timer_period` на H3 — ГЕРЦЫ, а не микросекунды → IRQ0-шторм
`pxt/src/emulator/i8253.c:151`: под `PICO_ON_DEVICE` пишется
`timer_period = divisor*1e6/PIT_FREQ` (мкс), в `#else` (H3) — `PIT_FREQ/divisor`
(герцы). Хост `pxt_host.c:644` читает как мкс:
`period = timer_period>0 ? timer_period : 54925`. При div=65536 герцы=18 →
период 18 мкс → **55 000 IRQ0/с** (гость захлёбывается; тот же класс, что
r1474/r1484 у МС1504). Фикс: `1000000ULL*div/PIT_FREQ` в `#else`.
Стенд не проверен.

### К2 [снято по коду r1488] pxt: повторный вход и кэш VGA-масок
Часть «повторный вход не сбрасывает кэш VGA-масок» **не подтвердилась**:
`reset86()` (cpu.c:1464) сам вызывает `vga_init()`, который `memset`-ит
`vga_cache_t` (sequencer[]/graphics_controller[]) и пересчитывает
`map_mask32`/`set_reset32`/`bit_mask32`. Отдельный `vga_init()` в `emu_run_pxt`
не нужен. Статус: закрыт.

### К4 [BUG→исправлено r1488] pxt: запись в BIOS-зону 0xFC000..0xFFFFF терялась молча
`memory.c:41-60`: в `write86_ob` не было ветки для `0xFC000..0xFFFFF` — запись
DOS-драйвера молча терялась (read86_ob читает `BIOS[]`/0xFC000→0x21).
r1488: явный задокументированный no-op (ROM — железо игнорирует запись, как
на реальном PC/XT) добавлен в `write86_ob`/`writew86_ob`/`writedw86_ob`;
`read86_ob` для 0xFC000 прокомментирована (сигнатура расширенного BIOS от
эталона). Статус: закрыт.

### К3 [BUG] МС1504: INT 1Ah AH=02/04 → newlib `time()/localtime()` без `_gettimeofday`
`bios.c:841-861`: `_gettimeofday()` возвращает −1 (libc_min.c:368) → `time()==(time_t)-1`
→ `localtime()` может вернуть NULL → чтение `t->tm_*` = обращение к NULL/RAM на
каждом RTC-вызове DOS. pxt это лечит (rtc_read, ports.c:108), МС1504 — нет.
Фикс: фиксированная `struct tm` (дата/время константа), как у pxt.

### К4 [BUG] pxt: дыра в чтении 0xC0000..0xFE000 (не EMS/UMB/BIOS)
`read86_ob` возвращает `0xFF` на мусорном диапазоне, запись — молча в пустоту;
`0xFC000` — хардкод 0x21 (из эталона). Экзотика, но не-выявленная потеря.

### W1 [DEVIATION] pxt: AdLib/OPL2 на H3 — тихое молчание (подтверждает PX-03)
`ports.c:328-332`: ветка H3 сохраняет рег. 0..4, статус 0x388 отвечает 0x80
(«OPL есть»), синтеза нет. `emu8950` не в `PXT_BONES` (Makefile:537).
Требует решения: собрать emu8950 или зафиксировать ограничение в docs.

### W2 [DEVIATION] pxt renderer `case 0x1e` проваливается в `0x07` с байтовым `start_off=5`
`pxt_host.c:214`: `start_off` (байты) накладывается на поэлементный
`VIDEORAM` в `0x07`. Режим недостижим (cga_portout 3B8), но при включении HGC — сломается.

### W3 [BUG] МС1504: спикер — низкая амплитуда и не сброшенная фаза
`shim.c:87-95`: `(speaker_ph >> 8)` даёт уровень ≤46/32767 (16%); при `gate=0`
фаза не двигается, аккумулятор не обнуляется → щелчок при включении.

### W4-W7/W6 (диски) — см. реестр: потоковый HDD RO (disks-h3:249), геометрия без
проверки цилиндров, XMS-хэндлы без размеров, RTC константа.

### S/N (мелочи): unused `vidramptr`, fallthrough, мёртвый `#if 0` в bios.c,
`swap.c`=пустышка в PXT_BONES, `printf_`→`pxt_printf_` корректен.

## 3. Клавиатура (кратко)

- МС1504: ASCII→BDA по умолчанию; сканкод-путь (0x60+IRQ1) только если INT9 ушёл
  из ROM (r1470/r1485-диагностика). F11 («0x57») = переключатель RU; в ASCII-пути
  F11-сканкод не доходит (host ведёт мод); RU-таблица CP866 — проверить кодировку
  знакогенератора МС1504.
- pxt: 8042-очередь + IRQ1 (корректно; mod-ы без E0 — исторически верно для XT).

## 5. Что НЕ проверено (честно)

- Построчная семантика интерпретаторов cpu.c (обоих) — сверены по диффу с эталоном
  и ключевым функциям, не по каждому опкоду.
- `emu8950.c`, `slot_render`, `wavetable/gm_bank`, `network-redirector` — не
  компилируются на H3 (в сборке отсутствуют), читались только заголовки.
- Поведение r1484..r1486 на стенде (железа в сессии нет).
- Точная кириллическая кодировка МС1504 (CP866 vs иная) — по BIOS-дампу не
  определяется (шрифт внешний).
