## 2. Критично

### K-01. FTP STOR поверх существующего файла оставляет дубль и освобождает чужую цепочку
`h3_bare/cores/fat.c:1180-1241, 1292-1317, 1341-1356, 779-908`.

`fat_write_begin()` ищет старую запись только чтобы запомнить `prev_first`
(`fat.c:1196-1198`), новую direntry пишет в свободный слот, а `fat_write_end()`
освобождает старую цепочку (`fat.c:1315`), не помечая старую direntry удалённой.
`fat_find()` возвращает первую запись, т.е. старую, указывающую на уже
освобождённые кластеры. Повторный STOR снова берёт `prev_first` из старой записи
и освобождает кластеры, которые FAT могла отдать другому файлу → порча данных.
Дополнительно `fat_delete_file()` отказывает при `first_cluster == 0`
(`fat.c:891`), поэтому 0-байтные файлы не удаляются и не перезаписываются.

### K-02. ZIP-буфер аркад перекрывает пул FBNeo и `.vice_bss`/`.fs_bss`
`h3_bare/cores/cps1_host.cpp:112-115, 779-784`; `h3_bare/platform/linker.ld:60-63`;
`cps1/burn/burn_memory.cpp:18,36`.

`ZIP_BUF1 = 0x50000000`, `ZIP_MAX = 92 МБ` → конец `0x55C00000`.
`.noinit_fbn`/`pool_mem` занимает `0x54000000..0x5A000000`, значит zip длиннее
64 МБ залезает в пул на 28 МБ. Центральный каталог zip (~конец файла) для сета
~84 МБ попадает в пул и затирается первым `_BurnMalloc` → ROM-сет не читается.

## 3. Важно

- **B-03.** `.vice_bss` кончается `0x53D95460`, assert — `<= 0x53E00000`
  (`linker.ld:142-151`), запас 175 КБ. Один `reSID::Filter::model_filter`
  (`nm`: `0x528CF630`, `0x01442060` = 21,2 МБ) съедает большую часть. Любое
  изменение сборки VICE упирается в assert.
- **R-01.** `printf.c:44-85, 123-129`: `vprintf/vfprintf` идут через `do_printf`,
  который не потребляет аргументы `%f`/точности → сдвиг `va_list` в логах VICE.
- **D-01.** `i2s.c:471-483, 650-665`: `i2s_ring_reset()` ставит паузу и делает
  FLUSH_TX, а CPU2 во внутреннем цикле пачки (до 24 пар) паузу не проверяет —
  возможен «доезд» старых пар после сброса.
- **D-02.** `i2s.c:181-192, 306-318, 493-494`: core0 пишет `s_dc_shift`,
  `s_dc_bypass`, `s_dc_lp_*` в `.coherent`, но делает только `dsb` (не чистку
  D-cache). `.coherent` — write-back (`h3.c:52-72`, `mmu_mark_uncached` — no-op),
  CPU2 читает DRAM → видит старое. Комментарии «uncached» неверны.
- **D-03.** `i2s.c:246-250, 616, 997-1003`: `g_stat_active`/`g_stat_underrun`
  читаются/пишутся CPU2 и core0 через кэшируемый `.bss` — гонка и stale.
- **D-05.** `usb_hc.c:87-197, 366-449`: EHCI-путь не делает cache maintenance для
  qH/qTD/буферов (в OHCI есть, `usb_ohci.c:334-361`) — DMA видит stale DRAM.
- **E-01.** `fb_text.c:20-33, 326-353` + `emu.c:81,145,274,387`: при включённой
  опции «Video: no tearing» скейлеры пишут в `FB_ADDR`, а `fb_flush` чистит и
  показывает `s_fb_draw` → каждый второй кадр stale/чёрный.
- **F-02.** См. K-01: 0-байтный файл нельзя удалить (`fat.c:891`).
- **F-03.** `fat.c:434-466, 317`: в пробе разделов не вычисляется
  `g_total_clusters` (остаётся 0), поэтому `read_dir()` сразу возвращает 0 и
  поиск раздела с `/roms` никогда не срабатывает; работает fallback «первый
  не-system раздел».
- **F-04.** `fat.c:990-1076`: `fat_write_file()` не откатывает выделенные
  кластеры/частичную запись при ошибке — lost clusters.
- **F-08.** `gba_mgba_host.c:218-247` + `emu.c:347-351`: `deinit` ядра GBA
  вызывается уже после `gb_heap_reset()` — use-after-reset по контракту.
- **A-02.** `cps1_host.cpp:840-858, 1033`: при ошибке `BurnDrvInit` нет
  `BurnDrvExit()`; после выхода нет `emu_audio_stop()`. То же отсутствие
  `emu_audio_stop()` — в fuse/bk/c64/a8/cpc/msx/pce host-слоях.

## 7. Что не проверено

- Вендорные ядра целиком (fuse/vice/gpgx/mgba/uae4all/cap32/atari800/fceumm/
  snes9x/picodrive/gambatte/handy/prosystem/yabause/pce/…): проверялись только
  наши host-слои и точки стыка.
- `h3_sdc.c` (6120 строк) — фрагментарно; `wifi_net.c`, `wpa_crypto.c`,
  `net_tcp.c`, `net_ftp.c` — интерфейсы и буферы, не весь протокол.
- `h3_de2.c`/`h3_hdmi.c` — частично, без сверки EDID/таймингов с PDF.
- `cps1_host.cpp:220-430,520-690` — частично.
- Аппаратная проверка (кэш-когерентность, тайминги I2S/SPI/SD, DE2 flip,
  EHCI/OHCI) не выполнялась.
- Сборка из свежего клона не выполнялась.

## 8. План правок (порядок = критичность/зависимости)

1. K-01/F-02: публикация direntry при перезаписи; удаление 0-байтных файлов.
2. K-02: ограничить ZIP-буфер 64 МБ (или перенести).
3. D-05: cache maintenance для EHCI (или оставить только OHCI).
4. D-02/D-03/B-06: когерентность `.coherent` (чистка/перенос в SRAM).
5. E-01: `fb_draw_addr()` в скейлерах + полная перерисовка при flip.
6. F-03/F-04/F-06/F-07: FAT-проба, откат записи, широкие кадры PCE/SNES.
7. R-01: `vprintf/vfprintf` через `vsnprintf`.
8. A-02/E-03: единый `emu_audio_stop()` на выходе host-слоёв.
9. R-06/R-07: wrap пар; диагностика звука в релизе.
10. R-04: сброс слотов/логов fs_layer.
11. D-01: проверка паузы внутри пачки CPU2.
12. D-04/B-02/F-05/F-10: мёртвый код/комментарии/`_hend`.
