**Новое по стенду (r1484):** диски pxt — `pxt_disk_set_stream()` ставит
`readonly = 1` (`disks-h3.c.inl:116`), запись отклоняется (`:249`), поэтому DOS
на C: пишет «запись невозможна»; B:/D: в эмулятор не попадают (в `emu_run_pxt`
ставится только A:). Эталон pico-286 пишет через FATFS (`f_open(FA_READ|FA_WRITE)`,
`f_write`, `disks-rp2350.c.inl:40,269`), у нас в FAT-слое есть только
последовательная запись (`fat_write_begin/data/end`), записи по смещению нет.
Плюс медленные чтения HDD: 250–460 мс на запрос (по-секторный поиск по FAT).

## 2. Что именно проверено при повторной сверке

- **MS-01 подтверждён и исправлен.** `usb_kbd_get_raw()` отдаёт только коды из
  6-байтного поля; модификаторы живут в `usb_kbd_get_mods()`. Цикл отпусканий
  (1..0x58) искал код в `raw[]` → `still == 0` → release сразу после press.
  Правка r1467: пропуск `0x1D/0x2A/0x36/0x38` в цикле отпусканий (как в PXT r1431).
- **MS-11 подтверждён и исправлен.** `ms1504_scale_to_hdmi()` растягивал
  640×400 → 960×600 (×1.5), т.е. символ 8×16 становился 12×24. r1469: вывод
  1:1 через `emu_show_rgb565_1to1(..., 192, 100)`.
- **MS-03 подтверждён документально.** `i8253.c:66` сам считает `tickgap` из
  `effectivedata[0]`, а шим берёт константу `PIT_IRQ0_US 54925`
  (`ms1504_shim.c:116`); `counter[0]` не декрементируется вовсе.
- **PX-05 снят.** `pxt/src/emulator/ports.c:53` — `doirq(1)` внутри `keyboard_push`.
- **PX-02 переформулирован.** Клампятся оба канала (`ports.c:649-650`), но
  сужение `(int16_t)mix` (`:641`) и присваивание в `int16_t` (`:654`) идут
  раньше клампа — заворот происходит до проверки.
- **PX-01 подтверждён и расширен.** `VIDEORAM` — `uint32_t[65536]`, индекс =
  байтовый адрес окна (`vga.c:173`, `memory.c:16`). Текст уже переведён на
  поэлементный доступ (`pxt_host.c:112,126`, r1413). Графических ветвей на
  `uint8_t*` — **восемь**, там двойная ошибка (база в 4 раза и шаг 1 байт).
- **PX-13 установлен стендом.** Слой DE2 с `TOP_LADDR = pxt_screen` не виден:
  r1463 — чёрный экран, r1466 — ровный `BKCOLOR` без растра. Слой с
  `TOP_LADDR = FB` рисуется. Вывод: на H3 UI-канал 1 работает только с буфером,
  который был задан в `de2_mode_set()`, либо запись конфигурации не защёлкивается.
  Аппаратный скейлер и UI-слой отложены, API оставлен в коде.

## 3. Открытые находки: детали и правки

### MS-02. Частота PC-спикера (В)
`acc += div`, переключение при `acc >= 1193182` на 44.1 кГц → `f ≈ 0.0185·div`
вместо `1193182/div`. Правка: считать в тиках PIT (`acc += 1193182/44100 ≈ 27`,
переключение при `acc >= div/2`), `div` брать из `effectivedata[2]`, не из
`chandata[2]`.

### MS-03. IRQ0 жёстко 54925 мкс (В)
Правка: период = `1193182/effectivedata[0]` мкс, декремент `counter[0]`, гейт
`i8253.active[0]` сохранить (он лечит BIOS-тест PIC, `ms1504_shim.c:127-128`).

### MS-04. Квант `exec86` (С)
Бюджет 4.77 МГц / 60 Гц ≈ 79 500 инструкций; сейчас 120 000 → гость на ~1.5×
быстрее своих же IRQ. Правка: квант от `dt`.

### MS-05. AdLib/SB у МС1504 (В, документация)
`MS1504_BONES` не содержит `adlib.c`/`blaster.c`/`audio.c`; в
`docs/ARCHITECTURE.md` раздел про МС1504 обещает AdLib/SB. Варианты: включить
emu8950 (как в PXT) или зафиксировать ограничение в `docs/CONTROLS.md`.

### MS-07. OBF и lock-клавиши (С)
1) `portram[0x64] |= 2`, но бит OBF (bit0) не ставится/снимается — программы,
поллящие 0x64, данных не видят.
2) Caps/Num/Scroll меняют только `RAM[0x417]`; сканкоды `0x3A/0x45/0x46` не
подаются (`bios.c:541`) → `INT 16h AH=1` и сканирующие программы защёлок не видят.
Риск средний: трогает BIOS-тест PIC, проверять на стенде.

### MS-08 / PX-12. Коллизия 0x37 (Н)
PrintScreen (`0x46`) и keypad `*` (`0x55`) дают один код; отпускание одной
снимает другую. Правка: счётчик удержаний на код либо убрать PrintScreen.

### MS-10. Не переключается русская раскладка (В, новый) — ПРОВЕРЕНО ПО КОДУ

Симптом: Shift работает (r1467), но RU-раскладка в зашитом русском DOS не включается.

Что подтверждено по таблице `ms1504_hid_to_pc()` (`ms1504_host.c:51-115`):

1. **E0-префиксов нет вообще.** Правые и левые модификаторы дают один код:
   `0xE0/0xE4 → 0x1D`, `0xE1/0xE5 → 0x2A`, `0xE2/0xE6 → 0x38`
   (`ms1504_host.c:111-113`). Для XT это исторически верно, но драйвер,
   различающий правый/левый Ctrl или Alt, такого различия не увидит.
2. **Сканкоды вообще не доставляются гостю.** Host не пишет порт `0x60` и не
   поднимает IRQ1: `feed_pc_key()` → `ms1504_kbd_feed()` (`bios.c:525-540`)
   кладёт **готовый ASCII** в BDA-буфер `0040:001E`. Значит драйвер, который
   вешает свой обработчик INT 9 и считает там `0x1D`/`0x2A`/`0x38`, не увидит
   ничего — ни модификаторов, ни защёлок.
3. **Lock-клавиши не дают сканкодов.** В таблице `0x39→0x3A`, `0x53→0x45`,
   `0x47→0x46` есть (`:82,83,89`), но `ms1504_kbd_feed()` для `0x3A/0x45/0x46`
   выходит сразу (`bios.c:541`), а host ведёт их отдельным списком защёлок и
   пишет только `RAM[0x417]`. Драйвер, ждущий сканкод, переключения не заметит.
4. **Коллизия `0x37`.** `0x46` (PrintScreen, `:88`) и `0x55` (keypad `*`, `:102`)
   дают один код. Нет `0x32` (non-US `#`) и `0x64` (102-я клавиша).

Вывод: причина не в модификаторах как таковых, а в **архитектуре ввода** —
ASCII-в-BDA вместо сканкодов через `0x60`+IRQ1. Пока драйвер не получает
сканкоды, любое переключение по Ctrl+Shift/Alt+Shift не сработает.

Порядок проверки и правки:
1. **Сделано в r1470.** В `ms1504_kbd_feed()` (`bios.c:532`): если вектор INT 9
   ушёл из ROM (`(IVT[9] >> 16) != 0xF000`) и IRQ1 размаскирован
   (`portin(0x21) & 0x02` == 0), сканкод отдаётся железным путём —
   `portram[0x60] = scan`, OBF (`portram[0x64] |= 1`), `doirq(1)`; иначе
   остаётся прежний ASCII-в-BDA. Проверка на стенде: RU-переключение и обычный
   ввод в DOS (регресс ASCII-пути).
2. Подавать сканкоды lock-клавиш `0x3A/0x45/0x46` (снимает и MS-07.2).
3. Проверить `BDA[0x417]` после r1467: биты Shift (0/1), Ctrl (2/3), Alt (3/7)
   должны обновляться; если нет — чинить `kbd_set_mod0()`.
4. Если драйвер ждёт правый Ctrl/Alt — вернуть E0-префикс для `0xE4/0xE6`
   отдельным режимом (для 286-совместимого BIOS это допустимо).


### PX-01. Восемь графических ветвей (В)
`pxt_host.c:108,175,191,207,230,244,255,292,330` используют
`(uint8_t*)VIDEORAM + 0x8000`. Нужно: `VIDEORAM[0x8000 + ((vram_offset & 0xffff) << 1) + …]`
для CGA/HGC, и `(VIDEORAM[idx] >> (plane*8)) & 0xFF` для Tandy/EGA. Режимы
`0x0D/0x0E/0x10/0x11/0x13` уже поэлементные — поэтому текст и VGA выглядят
нормально, а CGA/HGC/Tandy рассыпаются.

### PX-02. Кламп до сужения (В) — ПЕРЕПРОВЕРЕНО, БОЛЬШЕЙ ЧАСТЬЮ СНЯТО
В H3-ветке `get_sound_sample()` уже: кламп `mix` **до** сужения
(`ports.c:639-641`) и клампы обоих каналов после `cms_samples()`/
`blaster_samples()` (`:647-650`). Прежняя формулировка устарела.
Остаётся риск **внутри** `cms_samples()`/`blaster_samples()`, если они
суммируют в `int16_t` до клампа — это отдельная проверка, требует чтения
этих функций (`audio/*.inl`).

### PX-03. AdLib на H3 (В)
`emu8950.c` не в `PXT_BONES`, `OPL_new` не вызывается, `emu8950_opl` не
создаётся; `OPL_writeReg` без NULL-guard (`emu8950.c:1857`). Решение: включить
(замерив `.bss`/CPU) или зафиксировать ограничение.

### PX-04 / PX-08. Время в PXT (В/С)
IRQ0 — из `chandata[0]` (переменная `timer_period` уже есть, `i8253.c:21`).
Звук — генерировать `frames` из `dt`, а не 735 пар фиксированно.

### PX-06 / PX-07 / PX-09 / PX-10 / PX-11 (С/Н)
Сброс видеоглобалов (`hercules_mode` — `static` в `cga.c:7`, нужен reset-API);
`pxt_disk_clear(2/3)` перед монтированием; геометрия HDD с логом остатка;
`0x1e` — поэлементная арифметика; `_putchar` — проверка `x >= 80` до записи.

## 4. Оставшийся план

1. **Стенд r1469**: МС1504 — символы 8×16 (не «огромные»), PXT — кадр 640×480,
   растянутый в 800×600 без размытия. Если ок — пункт закрыт.
2. **MS-10** (RU-раскладка): гипотезы §3, начиная с E0-префиксов правых модификаторов.
3. **MS-07**: OBF + сканкоды lock-клавиш.
4. **MS-08/PX-12**: развести 0x37.
5. **MS-03 + MS-04**: PIT и квант у МС1504.
6. **MS-02**: спикер.
7. **PX-01**: восемь графических ветвей (самое дорогое по риску).
8. **PX-06/07/09/10/11**, затем PX-02, PX-04, PX-08.
9. **PX-03**: решение по AdLib.
10. Регресс-матрица: DOS, 3 игры, все режимы, две сессии подряд, `linkcheck`,
    бюджет `.bss` (`_bend1` ≤ 0x44C00000), сборка из свежего клона.

- `xms.c`, `ems.c.inl`, `mouse.c`, `swap.c` — только diff с эталоном.
- `emu8950.c` — не компилируется в сборке.
- `network-*.inl` pxt — не читались.
- Ветка `ET4000/0x1e` (HGC-совместимость) — по коду недостижима, нужна проверка замысла.
