# Формат Handheld Quake (.phq / .cfg)

> Полный разбор формата патронов «Handheld Quake» (Eugene Troitskiy, 2002–2005,
> http://www.emulator3000.org/hq.htm). Источник — инсталлятор
> `emulator-refs/[simulator]_handheld_quake_setup.exe`, распакован через
> innoextract; образы игр в `app/Games/*.phq`.
>
> Разбор сделан для оценки встраивания как пункта меню в раздел «портативные»
> bare-metal H3. Итог по числу машин — см. в конце.

## 1. Что это вообще такое

**Handheld Quake — НЕ эмулятор** в классическом смысле. Это **симулятор**
советских и зарубежных портативных LCD-электронных игр («Электроника ИМ-02/03/…»,
«MG-09», и клонов Nintendo «FP-24/…»).

Автор (Eugene Troitskiy, Москва, 2004) заново **перерисовал** спрайты оригинальных
OEM-игр и написал логику каждой игры **с нуля** на Windows. Образ патрона —
это набор ассетов + машино-логика, упакованные в один ZIP-файл.

Пакет поставляется как Inno Setup installer: `[simulator]_handheld_quake_setup.exe`
(имя — обёртка, к Quake-id не имеет отношения).

## 2. `.phq` — контейнер (ZIP)

Магия `50 4B 03 04` (`PK\x03\x04`) — обычный ZIP. Каждый патрон содержит:

| Тип | Примеры | Назначение |
|---|---|---|
| BMP-заголовки интерфейса | `AM.bmp`, `PM.bmp`, `Colon.bmp`, `One.bmp`, `GameA.bmp`, `GameB.bmp` | Служебные фрагменты экрана (календарь-индикаторы, разделители, кнопки A/B) |
| BMP-спрайты анимации | `ChickenLet0..3.bmp`, `EggDownLeft0..4.bmp`, `WolfLeft/Right.bmp`, `Hand0/1.bmp`, `BasketUp/DownLeft/Right.bmp` | Покадровые фрагменты игрового поля |
| BMP-сегменты | `SegmentA0..6.bmp`, `SegmentB0..6.bmp`, `SegmentC0..6.bmp` | 7-сегментные индикаторы счёта (по 7 кадров на разряд) |
| BMP-обложки | `Preview*.bmp`, `*_1.jpg`, `*_2.jpg` | Иконка и картинки в меню |
| WAV-звуки | `UpLeft.wav`, `Kick.wav`, `Loss.wav`, `Bell.wav`, `Finish.wav` | Эффекты |
| `*.cfg` | `IM02_JustYouWait.cfg` | Раскладка экрана + метаданные (бинарный, формат ниже) |
| `*.dll` | `IM02_JustYouWait.dll` | **Логика игры (PE-x86, см. §4)** |

BMP — крошечные (73–2000 Б, обычно монохром 1 бит/пиксель или 8-бит серый) —
фрагменты одного LCD-экрана.

## 3. `.cfg` — бинарная таблица раскладки

### 3.1 Заголовок (метаданные)

Записи вида `len byte + строка` (len — длина строки, строка без терминатора),
затем ключи `S<Name>`:

| Смещение | Поле | Пример (IM-02) |
|---|---|---|
| `0x00` | `u8 len` + `char[len]` | `0x14` + `IM02_JustYouWait.dll` |
| после | `u8 len` + `SName` | `SName` + `JustYouWait` |
| | `SModel` | `IM02` |
| | `SSeries` | `WideScreen` |
| | `SManufacturer` | `USSR` |
| (`u8 len`+`int year`) | `S...` | `1986` |
| | `SPhotographer` | `Constantine Golota` |
| | `SProgrammer` | `EugeneProgrammer` |
| | jpg 1 | `IM02_JustYouWait_1.jpg` |
| | jpg 2 | `IM02_JustYouWait_2.jpg` |

### 3.2 Таблица ресурсов (звуки)

После метаданных — последовательность:

```
u8  id;          // 0x00 .. 0x09 и т.д. (по возрастанию)
u8  len;         // длина имени
char name[len];  // "UpLeft.wav", "Kick.wav", ...
```

Запись ресурса-звука: `id` + `len` + имя. У звуков координат нет.

### 3.3 Таблица ресурсов (спрайты BMP)

Каждый спрайт-кадр:

```
u8  id;                 // 0x00=AM.bmp, 0x01=BasketDownLeft.bmp, ...
u8  len;                // длина имени
char name[len];         // "AM.bmp"
u8  reserved;           // 0x00
u16 x;                  // LE — горизонтальная позиция на экране
u16 y;                  // LE — вертикальная позиция
u16 w;                  // LE — ширина спрайта
u16 h;                  // LE — высота
```

Декодируя дамп: `\x06AM.bmp\x02\x00'\x00X\x00>\x00`
→ id=0x06, name="AM.bmp", reserved=0x00, **x**=0x0027=39, **y**=0x0058=88,
**w**=0x003E=62, **h**=0x0000? (в дампе `>\x00`). Уточнение по другим записям:
координаты и размеры хранятся как u16 LE.

Порядок id последователен: 0x06(AM) 0x07(BasketDownLeft) … 0x04A(SegmentA0)
… 0x49(ShellRight). Сегменты A/B/C индексируются одним id-диапазоном подряд.

### 3.4 Завершение (раскладка/кадры)

Хвост в дампе (после ShellRight.bmp, id `0x49`):
```
09 00 00 00 01 00 43 08 F3 00 74 00 45 00 02 00 44 08 A6 01 74 00 46 00 ...
```
Каждая запись: `idx(0x09..0x0D)` + `u32?` + 3×u16 + `02 00` ... — по-видимому,
описание **порядка/кадров анимации** (ссылки на id спрайта и тайминг). Точная
семантика этого хвоста требует сопоставления с `.dll`.

## 4. `.dll` — логика игры

`IM02_JustYouWait.dll` (12 288 Б) имеет сигнатуру **`4D 5A` (MZ)** — PE-образ
Windows x86. Содержит программу игры: таймеры, состояние, обработку A/B,
смену сегментов. Это **проприетарная логика автора**, бинарная.

## 6. Осуществимость встраивания в bare-metal H3

**Ассеты полностью открыты**: `.phq` — ZIP, `.cfg` читается (метаданные +
позиции спрайтов), BMP/WAV распаковываются. Статичное изображение экрана и
раскладка **портатируются напрямую**.

**Логика — закрыта и непереносима**: каждый вектор-игра завершается Windows
x86 `.dll` (MZ/PE), который на ARM без x86-эмуляции не исполняется. Формат
логики в `.dll` — байт-код приложения, а не декларативное описание.

→ **Встроить «как есть» нельзя.** Для пункта меню «портативные» потребуется
**переписать логику каждой из 17 игр** на C (таймеры/состояние/счёт/физика) и
связать с уже распарсенными ассетами `.cfg`/BMP/WAV. Это эквивалентно написанию
17 компактных аркадных мини-игр по готовым картинкам. Возможно, но это
отдельная многодневная разработка, не «подключение готового ядра».

## 7. Инструменты

- Распаковка инсталлятора: `innoextract` (скачан с GitHub в темп).
- Чтение `.phq`: любой ZIP (System.IO.Compression / 7-Zip).
- Документ не привязан к сборке прошивки; версия прошивки не затронута.
