# Слой 3 — ядра и интеграция (известные проблемы владельца)

Проверка по коду; правки не делаются. Каждая проблема получает ID и статус
«подтверждено / опровергнуто / требует данных».

## 1. Клавиатура отваливается при большом списке файлов на флешке

Проверено:
- Все USB-структуры и DMA-буферы — в `.coherent` (`usb_hc.c:65-68,234,262,
  399-402,481-485`; `usb_kbd.c:94-104`), т.е. не кэшируются и не пересекаются
  с `.bss`; `ASSERT(_coherent_end <= 0x4A40C000)` в линкере.
- Длинные control/bulk-передачи обслуживают клавиатуру: `usb_kbd_poll_block()`
  вызывается в обоих ожиданиях (`usb_ohci.c:678,868`, r990), с защитой от
  рекурсии GET_REPORT для Full-Speed.
- Общий скретч каталога `g_scratch_dir` (`fat.c:352`, ELF 0x4185A8C8,
  0x36B00 ≈ 219 КБ) используется 12 местами (`menu.c`, `rom_browser.c`,
  `disk_swap.c`, `cheatdb.c`, `ms1504_build.c`, `net_ftp.c`, `ep_host.cpp`,
  `main.c`). Вложенного затирания в проверенных путях нет:
  `fat_list` сначала делает `path_lookup` (он тоже пишет в скретч), затем
  `read_dir(out)`; `disk_swap` пересобирает список in-place; `menu` копирует
  имена в собственные `g_dir_names` (комментарий r0.417 M10 — этот класс уже
  закрывали).

**A-10 (P2, требует данных).** Класс «один скретч на всех» остаётся хрупким:
любой будущий вызов FAT-функции внутри обработки списка затрёт его. Признаков
порчи памяти по коду не найдено; для отвала клавиатуры нужен лог стенда
(`ohci-bulk: TIMEOUT`, `kbd_release_all`, число файлов в каталоге, порт/хаб).

## 2. «Песок» в звуке у части эмуляторов

Кандидаты по коду: общий полифазный ресемплер `rs44fs_*` (44100→48000) и
`i2s dc_shift` (6 у большинства хостов, 9 у аркад). Асимметрия темпа
(`nBurnSoundLen` от FPS драйвера против ровно 48 000) описана как A-05.
**A-11 (P2, требует данных):** нужен список систем, где слышен «песок», и
`AUDIO-END` (fill/drop/under) по каждой — иначе не отличить ресемплер от
недоливов кольца.

## 3. Автоопределение PAL/NTSC (игры идут быстрее)

`emu_period_us` задаётся драйвером/хостом (`cps1_host.cpp` — от `nBurnFPS`,
`emu.c` — дефолт), автодетект по кадру отсутствует. **A-12 (P2) — закрыто
(r1645):** у NES регион уже определялся FCEUmm, но терялся в хосте — он звал
`FCEUI_LoadGame("rom", …)`, а детект в `ines.c` ищет `(Europe)/(PAL)/(E)` в
имени файла. Теперь имя прокидывается из `emu_run_nes`; период кадра берётся
из `FSettings.PAL` (20 000 / 16 667 мкс). Для остальных систем автодетект по
кадру не делался: период у них уже идёт от реального FPS ядра.
Проверка: лог `NES: machine` — «PAL/Dendy» для Europe-ромов.

## 4. Мёртвый код / остатки экспериментов

Найдено: дубль `#define LOG_MEMORY_USAGE 0` (`burn_memory.cpp:9` и `:17`);
`static int cps_hw_scaler_active()` не используется (`cps1_host.cpp:565`);
`sourcefile_table` не используется (`driverlist.h:4022`). **A-13 (P3).**

## 5. Удаление файлов: постоянные ретраи в логе

Проверено по коду:
- `fat_delete_file()` (`fat.c:913-923`): находит запись (`find_dentry_loc`),
  помечает `0xE5` и пишет сектор; при ошибке `blk_read`/`blk_write` сразу
  возвращает -1. **Своих ретраев в этой функции нет.**
- Вызовы: `rom_browser.c:686` (двойное подтверждение, копия имени до удаления,
  `usb_wait_release_all`), `net_ftp.c:472`, `remap.c:435`.
- При `r != 0` браузер просто выходит в меню (`return`, `:696-699`) — без
  сообщения пользователю.

Значит «постоянные ретраи» приходят из нижележащего слоя записи сектора
(`blk_write`/USB bulk) или повторяются внешним клиентом (FTP). **A-14 (P2,
требует данных):** нужен фрагмент лога с текстом ретраев и сценарий
(браузер или FTP), плюс значение кода возврата `fat_delete_file`.

Отдельно **A-17 (P3):** неудачное удаление молча закрывает браузер — стоит
показать «Delete failed» и остаться в списке.

## 6. Загрузка ROM, свап дисков, эмуляция FAT

Проверено частично: `fat_read_file` возвращает -1 при неполном чтении
(`fat.c:1407-1415`), `fat_stream_read` — потоковое чтение (r1425/1430);
`fat_list` отдаёт `g_fat_dir_truncated` при обрыве (r1271). **A-15 (P2):**
нужны конкретные сценарии (какая система/образ, что в логе).

## 7. Помехи в звуке связаны с видео

Гипотеза о конфликте памяти: звуковые буферы хостов статические и лежат в
`.bss`/`.coherent` раздельно; кадровые буферы проверены (слой 2). Общий
скретч каталога (A-10) — единственная крупная общая зона. **A-16 (P2):**
проверять по логу `AUDIO-END` в момент помех + `nz/max` звука.

## 9. NEOGEO падает

Причина A-02 подтверждена расчётом (ROM-таблицы 85..89,5 МБ против пула
96 МБ, NULL без диагностики). Пул увеличен до 106 МБ в r1641 — ждёт проверки
на стенде.
