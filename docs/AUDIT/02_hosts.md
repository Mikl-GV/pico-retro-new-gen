# Слой 2 — хосты (кадровые и звуковые буферы, сверка с документацией)

Проверяется: размер кадрового буфера ≥ максимума, который может отдать ядро;
страйд/`pitch` при конвертации совпадает с буфером; чтение не выходит за
границы; звуковой буфер ≥ `nBurnSoundLen*2` и не соседствует с зоной, в
которую кто-то пишет.

## A-01 (P1, CPS/FBNeo) — кадр граничит с переменными NEOGEO

Подробно — `01_memory.md`. Кратко: `g_frame` 384×320 в `.bss`, сразу за ним
состояние NEOGEO-драйвера. Кламп `h ≤ 320` есть (`cps1_host.cpp:589`), а
ширина `w` берётся из `g_frame_w` с клампом `≤ CPS1_W` (`:586-587`), т.е.
переполнение возможно только через `nBurnPitch`/`BurnTransferCopy`, если
драйвер сообщает размер больше (требует проверки по списку драйверов).

## A-06 (P2) — звуковой буфер CPS: 4096 пар, ограничение 2048

`cps1_host.cpp:1113` `static int16_t cps_snd[4096]` (пар), при пуше
`n = nBurnSoundLen; if (n > 2048) n = 2048;` (`:1472-1473`). Для PS3
`nBurnSoundLen = 810` — запас есть. Но если драйвер отдаст > 2048, хвост
кадра **молча отбрасывается** (не переполнение, а потеря звука). Требует
проверки: максимум `nBurnSoundLen` по драйверам.

## A-07 (P3) — SNES hi-res сжимается до 320

`snes_host.cpp:353` клампит 512 до 320 — это не переполнение, но потеря
горизонтального разрешения в hi-res режимах. Сверить с `docs/` (нет ли
обещания 512).

## Звуковые буферы — проверено

| Хост | Буфер | Кламп | Статус |
|---|---|---|---|
| cps1/FBNeo | `cps_snd[4096]` пар | `n > 2048 → 2048` (`cps1_host.cpp:1496`) | **A-06** |
| GB | `gb_snd[1024*2]` | `np > 1024 → 1024` (`gameboy_host.cpp:265`) | ок |
| Coleco | `col_snd[GC_AUDIO_BUFFER_SIZE]` | `n > размер → размер` (`:259`) | ок |
| Lynx | буфер HANDY | кламп по `HANDY_AUDIO_BUFFER_SIZE/4` (`:242`) | ок |
| SNES | `sndbuf[4096]` | `frames > 2048 → 2048` (`:302`) | ок |
| GBA | `sndbuf[4096]` | `avail > 2048 → 2048` (`:335`) | ок |
| MSX | `st` | `Length > 2048 → 2048` (`:202`) | ок |
| MS1504 | `st` | `gen/n > 2048 → 2048` (`:556-559`) | ок |
| MD/GG/SMS | `abuf` | `n > 2048 → 2048` (`system_gpgx_h3.c:591`) | ок |
| PXT | `snd_buf[2048*2]` | `frames > 2048 → 2048` | ок |
| EP128 | `out` | `chunk > 2048 → 2048` (`:387`) | ок |
| Atari800/CPC/NGP/32X/A2600/BK/fuse/gw/pce | `out` | кламп не найден в строке пуша | требует проверки |

Правило: пуш всегда ≤ 2048 пар; буфер ≥ 2048 пар (4096 int16). Нарушение
означает потерю хвоста кадра (A-06) или переполнение (хуже).

## A-09 (P3) — CPC: нет клампов размера, безопасность на константах ядра

`cpc_render_frame` проверяет только `w<=0/h<=0` (`cpc_host.c:260`), а размеры
приходят из `retro_video.screen_render_width/height` (`video.c:128-133`).
Сейчас HI-режим даёт максимум 768×272 = ровно размер буфера
(`libretro-core.h:114-117`: `EMULATION_SCALE 2`, `CPC_SCREEN_WIDTH 384`;
`LOWRES` закомментирован). Переполнения нет, но любой сдвиг констант ядра
или включение `LOWRES`/иного crop выйдет за буфер в следующий объект
`.noinit_fbn`. Предложение (не утверждено): кламп `w<=768`, `h<=272` с логом.
