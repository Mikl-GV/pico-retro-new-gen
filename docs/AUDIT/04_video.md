## A-18 (P2) — нецелый вертикальный масштаб → дрожание строк в динамике

Все хосты масштабируют кадр на всю высоту FB (600 строк) с сохранением
пропорций: `dh = 600`, `dw = w*600/h` (`cps1_host.cpp:594-599`,
`host_render_frame:525-526`, аналогично в остальных хостах через
`h3_de2_ui_scaler_rect`). Для аркад 224 строки: 600/224 = 2.678; для NES/SNES
240 строк: 2.5; MD 224: 2.678. Коэффициент дробный, поэтому на каждый кадр
приходится разное число дублированных строк — при движении это читается как
«дрожание/плывущие строки».

Подтверждение из истории: r968 (CPC) убрал децимацию 768→320, которая давала
«неправильно собранные строки» и дрожание; там же масштаб сделан только
вверх. Значит класс проблемы известен.

Варианты (после утверждения):
1. Опция «целочисленный масштаб»: ×2 по вертикали (224→448) с чёрными полями
   сверху/снизу; строки не дублируются неравномерно — дрожания нет, картинка
   меньше.
2. Оставить дробный масштаб, но включить вертикальную интерполяцию в DE2
   (коэффициенты `h3_ui_scaler_coef`, 16 фаз) — сглаживание вместо «прыжка»
   строк; цена — лёгкая мягкость.
3. Компромисс: целочисленный ×2 для систем с 224/240 строк, дробный — только
   для крупных (CPC 272, Amiga 320).

Проверка: сравнить два режима на движущейся сцене (аркада/SNES), критерий —
отсутствие «бегущей» горизонтальной линии.

## A-19 (P3) — видеофильтра нет ни в коде, ни в настройках

Поиск по `h3_bare` (`video_filter|scanline|deflicker|smooth|bilinear`) не
нашёл реализации; в `settings.c` пункты `SET_*` (CREATE_FOLDERS, INPUT_TEST,
A2600_DIFF, SEGA_PAD, KEYBOARD_REMAP, TOUCH_CAL, PART_INFO, A2600_TV,
WIFI_TRANSFER, AUDIO_TONE, AUDIO_VOLUME) видеофильтра не содержат. Владелец
помнит опцию — вероятно, она была удалена вместе со старым программным
скейлером (r968/r1512 и далее).

Предложение (после утверждения): добавить пункт `SET_VIDEO_FILTER` с
вариантами `OFF / INTEGER / SMOOTH`, применить в общем месте выбора масштаба
(хосты зовут один хелпер), значение хранить в конфиге рядом с громкостью,
описать в `ARCHITECTURE.md` и в комментариях точек применения.

## Что осталось по слою

- Фактический режим DE2 проверен: скейлер уже использует таблицу
  `h3_ui_scaler_coef` (16 фаз, lan2coefftab16) и включается как
  `EN | COEFF_RDY` (`h3_de2.c:283-305`), т.е. фильтрация включена. Значит
  «дрожание» — не отсутствие фильтра, а дробный шаг при 2.678; вариант 1
  (целочисленный масштаб) остаётся основным.
- После утверждения — A-18/A-19 в работу (это правки кода).
