# Масштабирование изображения (CPU Integer Scale, Nearest Neighbour)

## Решение

Аппаратный скейлер DE2 (VI+VSU или UI+GSU1) на H3 в bare-metal **не завёлся** —
регистры не отвечали, гарантированного пути в обход ядра Linux нет.
Поэтому используется **CPU Integer Scale (nearest neighbour)**:

- Один общий буфер `EMU_FB` (0x5F800000, 320×240 RGB565 = 150 КБ)
- Каждый эмулятор пишет кадр в левый верхний угол `EMU_FB` в родном разрешении
- `emu_scale()` растягивает до HDMI FB (0x5F900000) целым множителем, по центру
- Чёткие пиксели, без размытия, ~0.5-1 мс на кадр на Cortex-A7

## Множители

| Система | Родной размер | Scale | Вывод на экран |
|---------|:-------------:|:-----:|:--------------:|
| **NES** | 256×240 | **×2** | 512×480 |
| **A2600** (MCUME) | 160×192 | **×3** | 480×576 |
| **A5200** | 320×240 | **×2** | 640×480 |
| **A7800** | 320×240 | **×2** | 640×480 |
| **SMS/GG** | 256×192 | **×3** | 768×576 |

## API

```c
// emu.h
void emu_scale(int src_w, int src_h, int scale);
```

- `src_w/src_h` — родное разрешение (кадр в левом верхнем углу EMU_FB)
- `scale` — целый множитель (2, 3)
- Картинка центрируется автоматически: dst_x/y = (1024/600 - dst)/2

Вызов: сразу после прорисовки кадра, перед `fb_flush()`.

## Реализация

```c
void emu_scale(int src_w, int src_h, int scale) {
    for (int sy = 0; sy < src_h; sy++)              // каждая строка источника
        for (int dy = 0; dy < scale; dy++)          // scale вертикальных копий
            for (int sx = 0; sx < src_w; sx++)      // каждый пиксель
                for (int dx = 0; dx < scale; dx++)  // scale горизонтальных копий
                    dst[base + ...] = RGB(src[sy*EMU_W+sx]);
}
```

Это чистый nearest neighbour: каждый исходный пиксель дублируется scale×scale раз.

## Память

| Адрес | Размер | Буфер |
|-------|-------:|-------|
| 0x5F800000 | 150 КБ | EMU_FB (320×240×2, один на всех) |
| 0x5F900000 | 2.4 МБ | HDMI FB (1024×600×4) |
| 0x50000000 | 24 МБ | ROM-буфер |

Распределение статичное, без heap, без утечек. Каждый host-слой сбрасывает
свой bump-аллокатор в `*_init_game`.

## История (почему так)

1. **VI+VSU** — чёрный экран (ROUTE=0 ломал трубу)
2. **UI+GSU1** — «градиент» без скейлинга, регистры GSU не читались
3. **CPU Integer Scale** — ✅ работает всегда, без зависимостей от железа

Эксперименты (h3_de2_scaler.c/.h) удалены из кода и из этого документа.
