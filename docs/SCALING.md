# Масштабирование изображения (Integer Scale, Nearest Neighbour)

## Цель

Каждый эмулятор выводит картинку в «родном» разрешении. Экран у нас
1024×600 — все родные картинки занимают меньше трети площади. Нужно
увеличить их без размытия и **без нагрузки на CPU**.

## Решение: аппаратный скейлер DE2 (VI-канал + VSU)

На H3 дисплейный движок DE2 умеет растягивать фреймбуфер аппаратно
через канал **VI** (Video Input) и блок **VSU** (Video Scaler Unit).
CPU в масштабировании не участвует: DE2 сам читает маленький буфер
из DRAM через DMA и выводит его увеличенным на нужную область экрана.

### Режимы DE2

| Режим | Канал | Описание |
|-------|-------|----------|
| **UI** (меню) | Channel 1 (UI) | 1024×600 XRGB8888 1:1, текст меню |
| **Emu** (игра) | Channel 0 (VI) + VSU | маленький фреймбуфер → увеличенное окно |

### Множители

| Система | Родной размер | Scale | Вывод на экран | Позиция (центр) |
|---------|:-------------:|:-----:|:--------------:|:---------------:|
| **NES** | 256×240 | **×2** | 512×480 | x=256, y=60 |
| **A2600** (MCUME) | 160×192 | **×3** | 480×576 | x=272, y=12 |
| **A5200** | 320×240 | **×2** | 640×480 | x=192, y=60 |
| **A7800** | 320×240 | **×2** | 640×480 | x=192, y=60 |
| **SMS/GG** | 256×192 | **×3** | 768×576 | x=128, y=12 |

Все множители — целые (nearest neighbour), пиксели остаются чёткими,
пропорции сохраняются (0.8–1.2 × по вертикали/горизонтали — незначительное
искажение, как на реальных ретро-ТВ).

### API

```c
// h3_de2_scaler.h
int  de2_set_emu_mode(int src_w, int src_h, int dst_w, int dst_h,
                      int dst_x, int dst_y, uint32_t fb_addr,
                      int format_rgb565);
void de2_set_ui_mode(uint32_t fb_addr);
int  de2_is_emu_mode(void);
```

Поток в host-слое эмулятора:

```c
// вход в игру
de2_set_emu_mode(NES_W, NES_H, NES_W*2, NES_H*2, 256, 60, FB_EMU, 1);

// каждый кадр: просто пишем пиксели в FB_EMU (маленький буфер), без блита

// выход
de2_set_ui_mode(FB_MENU);
```

### Порядок регистров

1. Выключить UI-канал (channel 1)
2. Настроить VI-канал (channel 0): формат, размер входа, координаты окна, pitch, адрес
3. Настроить VSU: входной/выходной размер, шаги (step = src<<20/dst), фазы 0
4. Записать коэффициенты VSU: для integer scale — один tap 1.0 (0x40000000)
5. Переключить blender ROUTE на VI
6. DBUFFER=1 (apply)

### Формулы

```
hstep = (src_w << 20) / dst_w    // VSU в 20-битном дробном формате
vstep = (src_h << 20) / dst_h
```

### Координаты окна

```
dst_x = (1024 - dst_w) / 2
dst_y = (600  - dst_h) / 2
```

## Fallback

Если VSU не заведётся на железе (не отрисует, чёрный экран) — остаётся
текущий CPU-блит (циклы в host-слоях). Он не удаляется, просто не вызывается
в emu-режиме. Переключение режимов:
- `main.c` / `menu.c`: выход из эмулятора → `de2_set_ui_mode()`
- `rom_browser.c` перед запуском → `de2_set_emu_mode()`

## Проверка на железе

1. Собрать: `cmake --build build`
2. Записать `build/h3_bare.bin`
3. Запустить любую игру — картинка должна быть увеличена в 2-3×
4. ESC — вернуться в меню, текст снова 1:1
5. Если картинки нет: UART подскажет, что произошло (log из h3_de2_scaler)
