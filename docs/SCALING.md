# Масштабирование изображения (Integer Scale, Nearest Neighbour)

## Цель

Каждый эмулятор выводит картинку в «родном» разрешении. Экран у нас
1024×600 — все родные картинки занимают меньше трети площади. Нужно
увеличить их без размытия и **без нагрузки на CPU**.

## Решение: аппаратный скейлер DE2 (UI-канал + GSU1)

На H3 простой RGB-скейлинг делается через **UI-канал** (channel 1) и блок
**GSU1** (Global Scaler Unit 1, адрес mixer0 + 0x30000). VI-канал предназначен
для YUV-видео и требует CSC, GSU1 же работает напрямую с RGB-буфером.

Регистры GSU1 (по sun8i_ui_scaler.h из ядра Linux):

| Смещение | Регистр | Назначение |
|----------|---------|------------|
| 0x00 | CTRL | EN (bit0), COEFF_RDY (bit4) |
| 0x10 | INSIZE | входной размер (W-1 в [15:0], H-1 в [31:16]) |
| 0x18 | HSTEP | горизонтальный шаг (src<<20 / dst) |
| 0x1c | VSTEP | вертикальный шаг |
| 0x20 | HPHS | фаза X (0 для integer) |
| 0x24 | VPHS | фаза Y (0) |
| 0x28 | OUTSIZE | выходной размер (W-1, H-1) |
| 0x40 | HCOEFF[32] | г-коэффициенты (фаза 0: tap0 = 0x40000000 = 1.0) |
| 0x140 | VCOEFF[32] | в-коэффициенты |

GSU1 включается **после** записи всех полей. Для integer scale коэффициенты —
один tap 1.0 (nearest neighbour, без размытия). CPU не участвует: DE2 читает
маленький буфер из DRAM через DMA.

### Режимы DE2

| Режим | Канал | Скейлер | Описание |
|-------|-------|---------|----------|
| **UI** (меню) | Channel 1 (UI) | GSU1 выкл | 1024×600 XRGB8888 1:1 |
| **Emu** (игра) | Channel 1 (UI) | GSU1 вкл | маленький RGB565 → окно |

Важно: **ROUTE blender остаётся 1** (та же труба, что и меню) — только
UI-канал меняет SIZE/OVL_SIZE, а GSU1 тянет картинку. Это отличается от
первой попытки с VI+VSU, где ROUTE=0 давал чёрный экран.

### Множители

| Система | Родной размер | Scale | Вывод на экран | Позиция (центр) |
|---------|:-------------:|:-----:|:--------------:|:---------------:|
| **NES** | 256×240 | **×2** | 512×480 | x=256, y=60 |
| **A2600** (MCUME) | 160×192 | **×3** | 480×576 | x=272, y=12 |
| **A5200** | 320×240 | **×2** | 640×480 | x=192, y=60 |
| **A7800** | 320×240 | **×2** | 640×480 | x=192, y=60 |
| **SMS/GG** | 256×192 | **×3** | 768×576 | x=128, y=12 |

### API

```c
// h3_de2_scaler.h
int  de2_set_emu_mode(int src_w, int src_h, int dst_w, int dst_h,
                      int dst_x, int dst_y, uint32_t fb_addr,
                      int format_rgb565);
void de2_set_ui_mode(uint32_t fb_addr);
int  de2_is_emu_mode(void);
void de2_scale_test(void);
```

### Порядок регистров

1. Настроить UI-канал (channel 1): ATTR (EN+формат), SIZE (вход src_w×src_h),
   COORD (позиция окна dst_x,dst_y), PITCH (bpp*src_w), TOP_LADDR (fb_addr),
   OVL_SIZE (dst_w×dst_h)
2. Настроить GSU1: INSIZE (src), HSTEP/VSTEP (src<<20/dst), фазы 0, OUTSIZE (dst)
3. Загрузить коэффициенты nearest (HCOEFF[0]=0x40000000, VCOEFF[0]=0x40000000, остальные 0)
4. Включить GSU1 (CTRL = EN | COEFF_RDY)
5. DBUFFER = 1 (apply)

### Формулы

```
hstep = (src_w << 20) / dst_w
vstep = (src_h << 20) / dst_h
```

### Координаты окна

```
dst_x = (1024 - dst_w) / 2
dst_y = (600  - dst_h) / 2
```

## Fallback

Если GSU1 не заведётся (не отрисует, чёрный экран) — остаётся текущий
CPU-блит (циклы в host-слоях). Он не удаляется, просто не вызывается в
emu-режиме. Переключение режимов:
- `main.c` / `menu.c`: выход из эмулятора → `de2_set_ui_mode()`
- `rom_browser.c` перед запуском → `de2_set_emu_mode()`

## Проверка на железе

1. Собрать: `cmake --build build`
2. Записать `build/h3_bare.bin`
3. Включить, войти в **Settings → 3 — DE2 Scale Test**
4. Если градиент 320×240 растянут в 640×480 — GSU1 работает
5. Если нет — UART покажет лог `DE2: GSU ...` с записанными регистрами
