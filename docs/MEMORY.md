# MEMORY — карта памяти и правила размещения (актуально r1270)

> Источник истины по адресам: `linker.ld` + `nm/readelf build/h3_bare.elf`.
> Значения ниже сняты с рабочей сборки **r1270** (linkcheck OK,
> `h3_bare.bin` ≈21.64 МБ; с r1225 в `.data` вшит Kickstart 1.3, 256 КБ).
> При изменении состава секций — обновлять этот файл.
> Правила безопасной работы с MMU — `docs/PITFALLS.md`; модель памяти —
> `docs/ARCHITECTURE.md`.

---

## 1. Главный принцип

**В любой момент запущен ровно один эмулятор.** Из этого следует:

- пулы перезанимаются между запусками: `emu_prepare()` сбрасывает
  `gb_heap_reset()` (bump-пул `.gb_heap`) и `newlib_heap_reset()`
  (sbrk-арена); `puae_heap_reset()` — отдельно для Amiga;
- при выходе из эмулятора: `emu_audio_stop()`/`i2s_ring_reset()`, DE2
  возвращается на штатный буфер;
- «зоны разных ядер» могут пересекаться по адресам, потому что simultaneity
  нет (например ROM_BUF и zip-буфер аркад, `.noinit_fbn` и DRAM-пулы).

**Правило:** память берём при запуске, отдаём при выходе; не добавляем
новых «жёстких» секций без `ASSERT` в `linker.ld` и без записи здесь.

## 3. SRAM A1 (0x00000000..0x00006000, без MMU у CPU1/CPU2)

Единственная зона, надёжно видимая всем трём ядрам (CPU1/CPU2 работают с
MMU off). Здесь живут почта, синхронизация и звуковое кольцо.

| Адрес | Назначение |
|---|---|
| `0x18` | one-shot гейт обработчиков исключений (сбрасывается в `_start`) |
| `0x20` | SMP-magic CPU1/CPU2 (`0x13579BDF`) |
| `0x24` | статус CPU1 (TFT): `0x0E` — прыжок в `tft_core_main`, `0xEF` — вернулись |
| `0x28..0x30` | пробы/диагностика SMP |
| `0x34..0x8C` | SRAM-почта: калибровка тача, кнопки, настройки |
| `0x90` | статус CPU2 (audio): `0xA2` — в трамплине |
| `0x94` | SRAM-дубль `g_i2s_ready` (CPU2 видит без MMU) |
| `0x98` | индекс кольца `wr` (продюсер core0) |
| `0x9C` | индекс кольца `rd` (потребитель CPU2) |
| `0xA0` | флаг синхронизации `ring_sync` |
| `0xC0` | стадия CPU2 (`g_cpu2_stage`) |
| `0x880..0x8A8` | счётчики/дамп исключений (DFAR/LR/DFSR/MPIDR) |
| `0x8B0` | TTBR0 загрузчика, сохранённый startup.S (r1200, диагностика) |
| `0x1000..0x2FFF` | кольцо звука L: 4096 × int16 (8 КБ) |
| `0x3000..0x4FFF` | кольцо звука R: 4096 × int16 (8 КБ) |

**Правило:** новые межъядерные флаги — только сюда (SRAM), не в DRAM:
направление core0→CPU2 через DRAM ненадёжно, а CPU2→core0 не работает вовсе
(история r928/r953 — индексы и кольцо поэтому в SRAM).

## 4. MMU: LPAE (long descriptors) — как устроено сейчас

Стенд: U-Boot 2025.01 работает в **LPAE** (`TTBCR.EAE=1`,
`TTBCR=0x80000F00`), таблицы 64-битные:

- `TTBR0 = 0x4A40C000` — **L0-копия** (4 КБ, 512 записей × 8 байт);
- записи L0 ссылаются на **L1-копии**: `0x4A410000`, `0x4A411000`,
  `0x4A412000`, `0x4A413000` (по 4 КБ; 2-МБ блоки);
- копии сделаны `startup.S` (r1202) ДО установки стека; оригинальные таблицы
  U-Boot лежат в `0x5FFF1000/0x5FFF2000` и **затираются стеком** — после
  копирования это безопасно;
- `TTBR1` — мусор, не используется (`TTBCR.N=0`, TTBR0 покрывает 4 ГБ).
  **TTBCR/TTBR0/TTBR1 не менять.**

MAIR (снято со стенда):

| MAIR | Значение | Индексы |
|---|---|---|
| `MAIR0` | `0xFFEEAA00` | 0 = Device-nGnRnE (периферия), 1 = `0xAA` (Normal WT), 2 = `0xEE` (Normal WB WA), 3 = `0xFF` (Normal WB WA) |
| `MAIR1` | `0x44E048E0` | 4 = `0xE0`, 5 = `0x48`, 6 = `0xE0`, **7 = `0x44` = Normal Non-cacheable** |

Фактические AttrIndx: **периферия = 0**, **DRAM = 2 (WB)**. Прочие индексы
принадлежат U-Boot — занимать их нельзя (r1203: подмена индекса 4 сломала
USB).

**Что можно/нельзя:**

- `mmu_mark_uncached()` — намеренный **no-op** (r1206): перевод `.coherent`
  в NC ломает OHCI (r1203/r1205). Когерентность держат `cache_clean/
  invalidate` (USB), SRAM-кольцо (r957) и SRAM-индексы (r929);
- любые правки карты — только 64-битными long-дескрипторами; short-формат
  в LPAE-таблицу писать нельзя (r1194-r1201 — не работало вообще);
- `AP[2:1]` в LPAE: `0b01` = RW (EL1+EL0), `0b11` = **RO** (r1202 поймал
  Permission fault на записи в HCCA);
- новые DMA-буферы: класть в `.coherent` (или отдельный регион), но
  **не менять атрибуты** без анализа последствий для OHCI.

## 5. Кто чем владеет (пулы и переиспользование)

| Зона | Владелец | Сброс/освобождение |
|---|---|---|
| `.gb_heap` 24 МБ | `malloc/calloc/realloc/free` в `gameboy_stubs.c` (все ядра) | `gb_heap_reset()` в `emu_prepare()`; A8 ставит `g_emu_keep_heap=1` |
| sbrk 48 МБ | newlib-куча + `puae_malloc/calloc/realloc/free/strdup` (Amiga) | `newlib_heap_reset()` в `emu_prepare()`; `puae_heap_reset()` в `emu_run_amiga` |
| `ROM_BUF` 0x50000000 (24 МБ) | `rom_browser.c:24` — загрузка ROM; `fs_layer`/`a8_fs` (образы C64/A8) | перезаписывается при каждом запуске ROM |
| `ZIP_BUF1` 0x50000000 (до 92 МБ) | `cps1_host.cpp:112` — zip аркад (NEOGEO ≈84 МБ), `ZIP_MAX` | перезаписывается при запуске аркады |
| `ZIP_BUF2` 0x5C000000 (48 МБ) | `cps1_host.cpp:113` — zip BIOS/родительского сета | только при запуске FBNeo/CPS |
| `.noinit_fbn` 96 МБ | FBNeo `pool_mem` (`_BurnMalloc`) | блоки обнуляются при выдаче; между аркадами не сбрасывается |
| `.vice_bss` 29.6 МБ | VICE (C64) | обнуляется `startup.S` один раз |
| `.a8_bss` 1.84 МБ | Atari 800 | обнуляется `startup.S` один раз |
| `.fs_bss` | `fs_layer.c` (слоты `g_files`, `g_rom_*`) | обнуляется `startup.S` |
| `EMU_FB` / `FB_ADDR` / back | `emu.c`: скейл, меню, все host-слои | `emu_prepare()`/`fb_clear()` |

**Пересечения по адресам — норма, если не одновременно** (владелец: единый
запуск). Точные перекрытия:

- `ZIP_BUF1` (92 МБ: 0x50000000..0x55C00000) накрывает `.vice_bss`
  (0x52000000..0x53D95460) и `.fs_bss` (0x53E00000..0x53E002DC). Аркады не
  используют `fs_layer` (CPS1/FBNeo читают ROM напрямую в ZIP_BUF1), а
  VICE-ядро и аркады вместе не запускаются — потому перекрытие допустимо;
- `.noinit_fbn` начинается 0x54000000 и может расти до 0x5C000000 (ASSERT);
- «свободно» в §2 для 0x51800000..0x52000000 и 0x5A000000..0x5C000000 —
  только если текущая система не заняла зону под zip/пул.

## 6. Периферия (не DRAM, Device-атрибут, индекс 0)

| Диапазон | Что |
|---|---|
| `0x01C00000..0x01C40000` | CCU, TWI, UART0 (THR 0x01C28000), GPIO, I2S0 |
| `0x01C1B400`, `0x01C1C400` | OHCI (USB) — регистры |
| `0x01C0F000`, `0x01C10000` | MMC0/MMC1 |
| `0x01C20000` | CCU (PLL, гейты, сбросы) |
| `0x01C30000` | GPIO/PIO |
| `0x01C20800` | PIO (мюксы PA/PG) |
| `0x01C80000`.. | GIC-400 (не используется: IRQ-путь снят) |

Обращения к периферии — только Device-атрибутом; менять AttrIndx периферии
нельзя (USB-регистры требуют строгого порядка).

## 7. Чек-лист при добавлении нового эмулятора/буфера

1. **Память — из существующих пулов:** `malloc` (`.gb_heap`) или собственный
   bump на sbrk; сброс — в `emu_prepare()`/своём `_reset`.
2. **Новую секцию** — только по образцу `.vice_bss`/`.a8_bss`: жёсткий VMA,
   `NOLOAD`, `ASSERT` на размер, обнуление в `startup.S`, запись в этот файл.
3. **Не занимать:** `0x5FF00000..0x60000000` (стеки core0), `0x5FBFD000..
   0x5FE01000` (стеки CPU1/CPU2), `0x4A40C000..0x4A420000` (таблицы LPAE),
   `0x4A400000..0x4A402FC0` (DMA-структуры OHCI).
4. **Межъядерная связь** — только SRAM A1; DRAM-флаги ненадёжны.
5. **MMU** — не трогать TTBCR/TTBR; при необходимости атрибутов — сначала
   прочитать MAIR и AttrIndx существующих записей (см. §4) и выбрать
   свободное, затем одна гипотеза = одна прошивка.
6. После изменений — `make clean && make`, обновить этот файл и
   `docs/HANDOVER.md`; при новом «грабле» — запись в `docs/PITFALLS.md`.

## 8. Быстрая сверка (команды)

```bash
arm-none-eabi-readelf -SW build/h3_bare.elf    # размеры/адреса секций
arm-none-eabi-nm build/h3_bare.elf | grep -E "_bstart1|_bend1|_gb_heap|_coherent|_menu_arena|_hend"
```

Эталонные значения r1270 (снято с `arm-none-eabi-nm build/h3_bare.elf`):
`_bstart1=0x415A2000`, `_bend1=0x44B3D850`, `_gb_heap_start=0x4A700000`,
`_gb_heap_end=0x4BF00000`, `_coherent_start=0x4A400000`,
`_coherent_end=0x4A402FC0`, `_menu_arena=0x4F000000`, `_hend=0x5A000000`.
Вшитые BIOS (`.data`): `puae_kick13_rom=0x413A91C0` (0x40000),
`puae_wb13_adf=0x413E91C0` (0xDC000, конец `0x414C8FC0`).
Имена сохранены от PUAE (r1243: сборка UAE4All переиспользует
`puae/kickstart_data.S`; собственной арены/статиков PUAE больше нет).

Стенд-маркеры (r1204/r1206, норма):
`LPAE[..]: ttbr0=4A40C000 mair0=FFEEAA00 mair1=44E048E0`,
`l0=…4A410003 …4A411003 …4A412003 …4A413003`,
`attr 01C00000=0 40000000=2 4A400000=2 4BF00000=2 5F800000=2`.
