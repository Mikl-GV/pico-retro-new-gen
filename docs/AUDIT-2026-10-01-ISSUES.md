## A. GBA (gpSP) — найдено субагентом, проверено вручную

- **A1 [КРИТ] cpu.cc:1507-1508, 578-586, 869** — `memory_map_read[pc_region]` и `fast_read_memory` без клампа адреса ≥0x10000000: сломанный PC (BX/POP PC в битой игре) даёт чтение за массивом (8192 элемента) и разыменование мусорного `pc_address_block` → Data Abort в bare-metal. Аналогично `ws_cyc_nseq[reg[REG_PC] >> 24]` (строки 2151, 3070, 3080, 3568, 3589, 1358) без маски `& 0xF`.
  Статус: **ИСПРАВЛЕНО r542** (Д-6): клампы в check_pc_region/execute_arm/arm_loop/thumb_loop, `& 0xF` во всех ws_cyc_nseq, open-bus в fast_read_memory/load_aligned32. Ждёт прогона на стенде.

- **A3 [СР] gba_memory.c:3125-3147, 3177-3190, 3016-3029** — чтение заголовка ROM (0xA0/0xAC/0xB2) без проверки минимального размера; `rom_scan_signatures_in_memory` (2994): `chunk_size - 10` при size<10 → огромный счётчик и чтение за ROM-буфером.   Статус: **ИСПРАВЛЕНО r542** (Д-6): арифметика в s64.

## B. Звук / I2S

- **B5 [КР/СР] Lynx: переполнение кольца I2S из-за жёсткого периода (найдено по стеночному отчёту, r548)** — симптом «звук очень плохой, отстаёт ~0.5с; тяжёлые игры тормозят». Причина: период = p*21 мкс (r511) не учитывал время эмуляции кадра (T_emu); на вывод звука оставалось меньше длины звука кадра → кольцо I2S (8192 пар) переполнялось за ~34 кадра (~0.45 с) → `i2s_push_sample` дропал ~37% сэмплов → хрипы/отставание. Исправлено r548: период = T_emu + p*21 + 400 мкс (кламп 8000..60000, T_emu caps 20 мс) — кольцо не растёт, звук выводится целиком.
  Статус: **ИСПРАВЛЕНО r548** (Д-12).

- **B6 [КР/СР] CPU простаивал ~13 мс/кадр на выводе звука (найдено по стеночному отчёту, r549)** — «полный провал» после r548: главное узкое место — `i2s_flush_max` с busy-wait 21 мкс/пара заставлял CPU «проигрывать» звук вместо эмуляции. Исправлено r549: неблокирующий FIFO-pump (≤24 пары) + долив порциями/udelay в throttle + подкачка внутри кадра Lynx. r550: уточнён механизм заполнения FIFO — вместо угаданного бита FIFO_STA bit6 используется аппаратный счётчик I2S_TX_CNT (порог 56/64 слов), убрано заикание от переполнения; период Lynx снова 75 Гц (адаптив r548 отменён).
  Статус: **ИСПРАВЛЕНО r549/r550** (Д-13/Д-14). Ждёт прогона на стенде.

- **B1 [СР] i2s.c:184-187** — «мягкий лимитер» только после клампа 32767/-32768: `L = 32767 + (L-32767)/4` может превысить 32767 + (65535-32767)/4 = 32767+8192 = 40959 → при касте в int16 обёртка → резкий щелчок/перекос. Проверить: нужен ли повторный кламп после лимитирования.
  Статус: **ИСПРАВЛЕНО r546** (Д-10): повторный кламп после сжатия.

- **B2 [СР] i2s_click / i2s_test_tone жёстко ставят `g_muted=1`** и принудительно гасят усилитель по завершении. Если во время клика/тона игра уже включила звук (g_muted=0 через push), то после клика усилитель будет замучен до следующего сэмпла — разовый щелчок тишины. Для меню некритично (там нет потока), но при вызове из игры — «провал» звука.
  Статус: **ИСПРАВЛЕНО r546** (Д-10): сохраняется и восстанавливается прежнее состояние мьюта (тоны/клики поверх игры не гасят усилитель).

- **B3 [СР] i2s.c:170** — авто-включение усилителя (PA10 HIGH) при первом сэмпле: если эмулятор «тихий» (нет сэмплов), усилитель остаётся выключен из-за mutes — но при входе в игру mutes=1 и SD=0 до первого сэмпла. ОК для игр со звуком; системы без звука (NGP/Portfolio) молчат — норм.

- **B4 [КОС] gba_host.c:219** — хардкод `sound_read_samples(sndbuf, 550)` — магическое число вместо `(32768 * 16) / 1000 ≈ 549`; комментарий в коде сам себя опровергает («~549»). Уточнить/вынести константу.
  Статус: **ИСПРАВЛЕНО r544** (Д-8): 549 с поясняющим комментарием.

## C. Память / карта (проверено по nm/size, 16 ядер)

- **C1 [ИНФО] BSS 48.8 МБ обнуляется на каждом старте** (`_bstart1=0x40CE5AC0 → _bend1=0x42B98098`). Плюс .noinit_fbn 96 МБ (NOLOAD, не обнуляется) до _gb_heap_start=0x48B980A0; куча 24 МБ до 0x4A3980A0; когерентная область 1 МБ на 0x4A400000; newlib-куча от 0x4A500000 до лимита 0x4F000000 (~4.75 МБ); ROM_BUF 0x50000000 (24 МБ); EMU_FB 0x5F800000; FB 0x5F900000; стеки 0x5FF0xxxx/0x5FE... — пересечений НЕТ, карта консистентна.
