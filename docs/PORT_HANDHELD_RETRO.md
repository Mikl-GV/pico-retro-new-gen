# Порт эмуляторов портативных LCD-игр (Электроника ИМ / Handheld Quake) на H3

> Разбор и план интеграции как отдельного пункта меню в раздел «портативные».
> Исходники для разбора: `emulator-refs/[simulator]_handheld_quake_setup.exe`
> (набор патронов .phq), репозиторий `artyomsoft/nupogodi-sdl` (готовый
> эмулятор микроконтроллера КБ1013ВК1-2 / Sharp SM-510), MAME (Game & Watch).

---

## 1. Суть: это НЕ «нужный» для Quake — это LCD-эмулятор

**Handheld Quake** (Eugene Troitskiy, 2002–2005) — **симулятор** советских и
зарубежных портативных LCD-электронных игр («Электроника ИМ-02/03/…», MG-09,
клонов Nintendo «FP-24/…»). В названии «Quake» — совпадение; к Quake-id оно
отношения не имеет.

**Устройство образов `.phq`** (полный разбор — в `FORMAT_HANDHELD_QUAKE.md`):
- `.phq` = ZIP. Внутри — **растровые сегменты** (`.bmp`), звуки (`.wav`),
  конфиг-раскладку (`.cfg`, бинарный), обложки (`.jpg`) и **логику в `.dll`**
  (PE-x86) — проприетарную, на ARM не запускается.

**Ключевой вывод по .phq:** сегменты внутри `.phq` — **зашифрованы** (байты
начинаются не с `BM`/PNG, а псевдослучайно), ключ живёт в `HandheldQuake.exe`.
Взять их «как есть» нельзя. Зато **логику каждой игры реконструировать не нужно**
для тех, что есть в MAME/готовых эмуляторах (см. §3).

## 2. Железо и механика LCD (почему «изображение готово, его подсвечивают»)

Портативные игры типа Game & Watch / «Электроника ИМ» построены на
микроконтроллере с собственным ЖК-драйвером. Наш пример — **ИМ-02 «Ну, погоди!»**
на советском **КБ1013ВК1-2** (аналог Sharp **SM-510**).

- **Экран — готовое LCD-полотно** с фиксированными сегментами (зайчик, волк,
  корзины, яйца, цифры). Микроконтроллер **не перерисовывает экран**, а по
  битовой маске **зажигает/гасит** сегменты.
- Программная модель в эмуляторе (`artyomsoft/nupogodi-sdl`):
  - микроконтроллер SM-510 эмулируется в `cpu/*.c` (регистры, опкоды, RAM);
  - порты вывода `m_o[9]` и `m_ox[9]` (O / AUX);
  - `update_segments_state()` копирует `m_o`→`m_o_state`, `m_ox`→`m_ox_state`;
  - сегмент `[i][j][0]` виден, если `m_o_state[i] & (1<<j)`,
    сегмент `[i][j][1]` — если `m_ox_state[i] & (1<<j)`;
  - сегменты — заранее растеризованные кусочки SVG (по `<title>i.j.k</title>`),
    текстуры; рисуются поверх `fg.png` (корпус LCD) если видимы.

То есть **рендер дёшев**: 9×4×2 = 72 сегмента, только видимые копируются.

## 3. Готовые реализации логики (что взять за основу)

| Источник | Что даёт | Вердикт для H3 |
|---|---|---|
| `artyomsoft/nupogodi-sdl` (GitHub) | **Полный C-эмулятор микроконтроллера SM-510 + прошивка `im-02.bin` (1856 Б) + `nupogodi.svg` + `fg.png` + SDL-обвязка** | **Лучшая база.** CPU-часть — чистый C, переносится напрямую. SDL — только ввод/звук/рендер, заменяется нашими. |
| MAME (`gameandwatch.cpp`) | Эмуляция тех же G&W/Электроника, но **SVG растеризуется каждый кадр** → тормоза на слабом CPU (наш H3, Pi Zero 2W — слайд-шоу) | Не использовать как рендер. Брать только прошивки/логику при отсутствии исходников. |
| `SeamusWaldron/nu-pogodi` (Go), `Hanka8` (JS) | Реплики ИМ-02 | Справочные, для понимания механики. |
| Handheld Quake `.phq` | Ассеты + закрытая x86-логика | Только как «картинки напоминания»; шифр не вскрываем без надобности. |

Советские «Электроника ИМ» = клоны конкретных Nintendo G&W (по Game&Watch Wiki):
- ИМ-02 «Ну, погоди!» = EG-26 Egg
- ИМ-03 «Тайны океана» = OC-22 Octopus
- ИМ-04 «Весёлый повар» = FP-24 Chef

## 4. План интеграции в раздел «портативные» H3

### 4.1 Что переносим из `nupogodi-sdl` без изменений
- `cpu/core.c`, `cpu/core.h`, `cpu/operations.c`, `cpu/operations.h` — эмулятор
  SM-510 (чистый C, `#include <stdint.h>` и т.п.).
- `device/rom.c` (функция чтения прошивки), `device/rom.h`.
- `device/system.c/h` (`system_run(cycles)` → `device_run()`).
- `device/def.h` (типы, `SYS_FREQ=32768`, `FRAMES_PS=30`).

### 4.2 Что переносим с адаптацией
- `nupogodi-sdl.c`: главный цикл `system_run(SYS_FREQ/FRAMES_PS)` → в наш хост.
- `resource/nupogodi/im-02.bin` (1856 Б) — вшить в прошивку (правило владельца:
  BIOS/ROM не с SD).
- `nupogodi.svg` + `fg.png` — **при сборке** преобразовать в 72 предрастеризованных
  сегмента (RGBA) + корпус; на кадре только копировать видимые в `EMU_FB`/`fb`.
- `device/graphic.c` — заменить SDL-вызовы на наши (`fb_*`/`fb_flush`,
  `emu_show_rgba_int`/`emu_show`), копирование текстур по `m_o_state/m_ox_state`.
- `device/sound.c` — динамик/зуммер через R-порт → `i2s_push_block` (пары L/R).
- `device/input.c` — `get_buttons()`/`readK` (A/B Game, 4 кнопки) → клавиши +
  Sega-геймпад `pad_scan_combined()`.

### 4.3 Интеграция в меню
- Новый пункт/подраздел «портативные» → эмулятор играет `im-02.bin` прямо из
  прошивки (без выбора файла) или список `.phq`-патронов для прочих игр.
- `emu_disk_ops_t`/`emu_disk_poll` (F12-свап) — не нужен; игр несколько, у каждой
  свой параметр (выбор игры в подменю).
- Версия прошивки, HANDOVER, MEMORY — по правилам проекта.

### 4.4 Осторожность по правилам проекта
- Не отключать существующие ядра; новый host-слой из отдельного .c линкуется в
  конец `$(OBJ)` (иначе сдвиг literal-pools ломает USB).
- `make clean && make` после правки `.h`. Адреса `usb_kbd_init`/
  `usb_ohci_ctrl_transfer` сверять с эталоном.
- Звук — парами (L,R) в I2S, CPU2 — единственный писатель TX FIFO.

## 5. Выполнимость: карта «наша игра → источник → что брать»

Решающий факт (по MAME driver `handheld/hh_sm510.cpp` и mdk.cab): советские
«Электроника ИМ» — это **нелицензионные клоны конкретных Nintendo Game & Watch**,
и **почти все они уже эмулируются в MAME** с готовыми прошивками микроконтроллера
SM-510 (`*.bin`) и SVG-экранами (`*.svg`).

Полный ром-сет отдельной игры (пример `nupogodi`):
- `im-02.bin` 1.81 КБ (CRC `cb820c32`) — прошивка КБ1013ВК1-2 (SM-510);
- `nupogodi.svg` ~150 КБ — векторный LCD-экран с сегментами;
- драйвер `hh_sm510.cpp` (SM5A, 32 кГц), статус `good`, требует artwork.

**Вывод по выполнимости:**
1. **Большинство из 17 — реально переносимы** из MAME: есть прошивка SM-510 +
   SVG-сегменты, и работает уже эмулирующая логика (тот же микроконтроллер,

   под каждую игру добавляется: `.bin` + `.svg` + сегменты (своя раскладка

3. **Исключения (уникальные советские, аналога в G&W нет):** ИМ-23 «Автослалом»
   (и возможно IM-50 вариации). Для них прошивки в MAME нет — логика
   переписывается вручную по видео/картинкам, либо остаётся "план".
4. **Авторские права:** прошивки/изображения охраняются; включаем как
   референсный материал, без распространения в Git (как ROM/BIOS — вшиваем,
   в репозиторий не кладём).

## 6. Итог оценки

- **Задача выполнима — и масштабируема на всю серию.** Ключевое открытие:
  почти все 17 «Электроника ИМ» из Handheld Quake — клоны конкретных
  Nintendo Game & Watch, которые **уже эмулируются в MAME** с готовыми
  прошивками микроконтроллера SM-510 и SVG-экранами.
- **Один общий CPU-эмулятор SM-510** (из `artyomsoft/nupogodi-sdl`) покрывает
  практически все игры: под каждую добавляется только `.bin` + `.svg` +
  раскладка сегментов + число кнопок. Это не 17 разных ядер, а одно ядро
  + 17 наборов данных.
- **Первое подтверждённое ядро** (`nupogodi-sdl`, ИМ-02) переносится напрямую:
  CPU-часть чистый C, ROM вшивается, рендер по предрастеризованным сегментам
  идеален для H3 (никакого SVG на лету).
- **Исключения:** уникальные советские игры без японского аналога (ИМ-23
  «Автослалом», часть IM-50) — прошивок в MAME нет, их логику придётся
  переписывать вручную (это останется «планом», не автоматической портацией).
- **Авторские права:** прошивки/изображения охраняются; включаем как
  референсный материал, без распространения в Git (как ROM/BIOS — вшиваем,
  в репозиторий не кладём).
- **Рекомендуемый план:** перенести общий SM-510-эмулятор как ядро, затем
  подключать игры по одной — сначала все, чьи ROM/SVG есть в MAME (готовая
  эмуляция уже подтверждена), потом вручную добить уникальные.
