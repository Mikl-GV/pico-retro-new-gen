# АУДИТ АРХИТЕКТУРЫ — pico-retro-new-gen r703 (2026-10-04)

Глубокий технический аудит по 5 слоям: карта памяти/линкер, MMU/когерентность,
межъядерное CPU0↔CPU2 (аудио), RMW-гонки PA_DAT, сверка с эталонными ядрами
(libretro). Проводился по исходникам r703 + свежему ELF (сборка из холодного
клона, linkcheck OK) + эталонным репозиториям (см. ниже).

## 1. КАРТА ПАМЯТИ И ЛИНКЕР (r703, из ELF)

```
.text rodata .data .bss    40000000 → 42B986B8   (bss ≈ 30.7МБ, aligned 64)
.noinit_fbn (NOLOAD)       42B986B8 → 431986B8   (96 МБ, ровно 0x6000000)
_gb_heap                   42B986C0 → 4A3986C0   (24 МБ)
_hend / _coherent_start    4A400000 (ALIGN 1МБ)  ✓
.libh3_coherent (NOLOAD)   4A400000 → 4A408747   (1 МБ окно)
_menu_arena                4F000000
ROM_BUF                    50000000 (ROM_MAX 24МБ)
EMU_FB 5F800000 / HDMI FB 5F900000 / стеки 5FBFD000..60000000
```

- Выравнивание корректно: `.coherent` ровно на 1МБ-границе; кольцо aligned(8);
  индексы/почта/все 32-бит поля `.coherent` aligned(4) → на CPU2 (MMU off)
  Alignment Data Abort от них невозможен. `int16_t`-загрузки по нечётному
  адресу (LDRH) на ARMv7 разрешены — безопасно.
- `.noinit_fbn` 96МБ + `_gb_heap` 24МБ не пересекаются; запас до конца DRAM
  огромен.
- Newlib-куча: `SBRK_START = libh3_coherent_region + 1МБ = 0x4A500000`,
  лимит `0x4F000000` → 75 МБ. Старт кучи — ДРУГАЯ 1МБ-секция (0x4A500000),
  чем uncached-окно 0x4A400000 → куча кэшируемая (правильно). Перекрытий нет.

## 2. MMU / КОГЕРЕНТНОСТЬ / МЕЖЪЯДЕРНОЕ

- Схема CPU0(MMU on)/CPU2(off), `.coherent` = uncached — архитектурно верна.
- Барьеры в наличии: `dmb sy` перед `g_ring_wr++` (продюсер), перед атомарным
  `g_ring_rd++` (CPU2), cmd→dmb→seq в почте, dmb в CPU2 poll_cmd.

### R1 (ВЫСОКИЙ): i2s_init() пишет .coherent ДО mmu_mark_uncached()
- `main.c`: `i2s_init()` (стр. 299) → внутри `pa_dat_request(SD_PIN,1)` +
  `pa_dat_apply_desired()` (i2s.c:346-348) — запись `g_pa_shadow` (.coherent)
  в момент, когда секция ЕЩЁ кэшируемая (U-Boot flat 1MB write-back).
- `mmu_mark_uncached()` вызывается ПОЗЖЕ (main.c:320), он меняет атрибут
  секции + инвалидирует TLB, но НЕ чистит D-cache: dirty-строка g_pa_shadow
  может «выстрелить» позже → CPU2 (читает DRAM напрямую) увидит PA10=0 и
  будет держать усилитель выключенным до первого рантайм-обращения
  (тишина/не включается звук), либо core0 увидит stale.
- Исправление: `mmu_mark_uncached()` ДО `i2s_init()` (или DCCIMVAC по
  .coherent перед переключением атрибута). См. дельту r704.

### R2 (СРЕДНИЙ): newlib-куча bump-аллокатором без free
- Куча 75МБ, `newlib_heap_reset()` в `emu_prepare` сбрасывается между играми,
  НО аллокации ВНУТРИ цикла кадров (run_frame) копятся до лимита → `_sbrk`
  вернёт -1 → падение ядра. Проверить на стенде длительную игру SNES/GBA/NGP.
- Статус: наблюдение, правка не требуется до появления симптома.

### R3 (НИЗКИЙ): ring_trim_atomic без dmb после STREX
- В `ring_trim_atomic` (i2s.c) после STREX нет `dmb sy` — продюсер двигает
  `g_ring_rd` (CAS), CPU2 читает его; крайне маловероятная гонка. Добавить
  `dmb sy` за копейки (см. дельту r704).

## 3. RMW-ГОНКИ PA_DAT

Как было (до r703): PA_DAT делили CPU0 (PA10 i2s-SD, PA15 SD-LED) и CPU1
(PA21 CS тача, PA2 RST TFT) → неатомарные |= / &= по регистру между ядрами.

Как стало (r703) — гонка архитектурно УСТРАНЕНА:
- CS тача PA21 → PC4 (перепайка), RST PA2 — только одноразовый init;
- CPU1 в рантайме PA_DAT не трогает (0x74-заморозка в игре; RST до старта CPU2);
- PA10/PA15: `g_pa_shadow` (.coherent) ← core0 (`pa_dat_request`, dmb st),
  применяет ТОЛЬКО CPU2 (`pa_dat_apply_desired` в цикле, сохраняя не-рантайм
  биты через PA_RUNTIME_BITS); i2s_mute/push_sample/тон/клик — через shadow +
  apply_if_core0 (при владельце CPU2 не пишет регистр сам).

Остаточные риски:
- `pa_dat_apply_desired()` (CPU2) — RMW регистра, но единственный писатель
  рантайм-битов, гонки нет (держать инвариант «PA_DAT пишет только CPU2»).
- `led_sd_toggle()` — только shadow, ок.

## 4. СВЕРКА С ЭТАЛОНАМИ

### Coleco (Gearcoleco)
- Порт 1:1 повторяет эталон `platforms/libretro/libretro.cpp`
  (load_colecovision_firmware): СНАЧАЛА LoadBiosFromBuffer (иначе
  IsBiosLoaded=false, машина не ready), ПОТОМ LoadAdamFirmware(OS7). CRC 0x3AA93EF3.
- gc_rename.sh (blargg) + linkcheck — дубликатов в ELF 0.

### GBA (gpSP, интерпретатор)
- Маппинг ROM на ROM_BUF напрямую (load_gamepak_raw при g_ram_rom) — 1:1
  с эталоном (только вместо filestream — указатель). map_rom_entry покрывает
  0x8000000..0x0C000000 зеркалами.
- selected_boot_mode=boot_bios — старт через вшитый BIOS, как libretro-gpSP.
- Запас производительности: 1.2ГГц A7, интерпретатор, dyarec OFF, frame-skip
  НЕТ (skip_next_frame=0). Тяжёлые игры могут недотягивать 60fps → latency,
  звук (CPU2) не страдает. Рекомендация: замер fps, при просадке — condition skip.

### SNES (Snes9x 2005, -DLAGFIX)
- Размерность звука подтверждена по эталону: MixBuffer интерливирован стерео,
  S9xMixSamples(buf, frames<<1) — host читает buf[2i], buf[2i+1] корректно.
- Settings.PAL ставится в LoadROM (memmap.c:1384-1402) — host использует
  50/60Hz — совпадает с эталоном.

### BK/Vectrex — прямой рендер в HDMI FB
- bk_host.c:174 / vecx_host.c:127 пишут напрямую в 0x5F900000 (минуя EMU_FB/
  emu_scale) — риск TEARING (HDMI читает буфер в момент записи). Закрыт за
  CONFIG_HDMI_DOUBLE_BUF (0 по умолчанию, решение владельца). Порчи памяти нет
  (ровно 1024×600×4 в свой буфер, стеки/банки исключений не пересекаются).

### NGP (race, blip)
- neopopsound.c / neopop_blip.c — 1:1 с эталоном race (include types.h→StdAfx.h).
  Осознанное отличие: шумовой порог `if (s > -16 && s < 16) s = 0` (r631/634) —
  фильтр floating-дрейфа DC-блокера в тишине (задокументирован).
- sound.cpp vs sound.c: добавлен `elapsed<1 → elapsed=1` (защита от вечного
  цикла на неопознанном opcode Z80) — улучшение относительно эталона.

## 5. ТИПИЗАЦИЯ / C/C++ / extern "C"

- extern "C" обёртки корректны (i2s.h, led.h, snes_host, host-функции).
- Сборка из холодного клона: -Wall -Wextra 0 предупреждений в своём коде.
