СТАТУС: 19 систем + аркадные семейства FBNeo: CPS-1/CPS-2, NEOGEO/MVS, Toaplan,
Cave (68K-эра) и Sega System 16/18 (см. docs/ARCADES-PLAN.md). CPU в дереве:

ЖЕЛЕЗО-ФАКТ: HDMI-панель стоит ФИЗИЧЕСКИ ПОРТРЕТНО (повёрнута на 90°) для игр,
которые имеют портретную ориентацию. Эффективный экран портретной панели = 600×1024.
Буфер HDMI при этом 1024×600, DE2 настроен слоем 1:1 (GSU-масштабирование НЕ
используется). Поворот вертикальных игр делает ФИЗИЧЕСКИЙ поворот панели,
программного транспонирования в коде НЕТ и не должно быть.

РЕНДЕР (h3_bare/cores/cps1_host.cpp, host_render_frame, r0.376):
- Для ВСЕХ игр (CPS/NEO/Toaplan/прочие) — ОДИН путь: «вписать по родному
  разрешению» — один равномерный коэффициент на обе оси (min(1024/W, 600/H)),
  центр всегда (511,299) в альбомных 1024×600, поля чёрные, НИЧЕГО не режется
  и не искажается. Масштаб — CPU nearest neighbour, шаги 16.16 (r0.360/r0.364;
  НИКОГДА не вставлять деление/умножение int64 в пиксельный цикл).
- Toaplan выводится КАК РОДНОЕ ЖЕЛЕЗО: кадр ядра как есть (без кропа, без
  транспонирования). Вертикальные игры ядро рисует «боком» в альбомный буфер
  320×240 (bToaRotateScreen=false в toaplan.h, DRIVER_ROTATION выключен);
  физический портретный поворот панели ставит их ровно. g_rot=0 ВСЕГДА.
  Для кадра 320×240 это даёт на панели 600×800 (масштаб ×2.5, по меньшей
  стороне 600), для 280×240 — 600×700. Поля сверху/снизу чёрные.
- Блок `if (g_rot)` в host_render_frame НЕ ИСПОЛЬЗУЕТСЯ (g_rot=0 всегда);
  можно удалить как мёртвый код, если не планируется программный TATE.

ВВОД Toaplan (r0.370): Slap Fight и MISC-платы читают кнопки через AY8910
port A/B (звуковой Z80 опрашивает DrvInputs и кладёт их в ShareRAM для main).
AY8910 эмулируется портовым стабом (cps1_stubs.cpp): звук off (nBurnSoundRate=0),
но порты/ввод/DIP работают. Настоящее ядро ay8910.c из линковки исключено.
