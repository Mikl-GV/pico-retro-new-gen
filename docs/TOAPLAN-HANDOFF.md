Ты — эксперт по низкоуровневому программированию на Allwinner H3.
Проект: bare-metal мультисистемный эмулятор на Orange Pi Lite (H3, 4×Cortex-A7),

Тулчейн xPack arm-none-eabi-gcc 15.2.1. Бинарь build/h3_bare.bin -> корень h3_bare.bin.
Версию баннера поднимать при КАЖДОЙ сборке: h3_bare/src/main.c (r0.363 сейчас).
ВНИМАНИЕ: после правки ЛЮБОГО .h обязателен clean && make (зависимостей на .h нет).

СТАТУС: работают 19 систем + CPS-1/CPS-2 + NEOGEO + Toaplan (~145 игр:
68K, NEC V25/V30, TMS32010, Z180, M6805 — все CPU в дереве h3_bare/cores/cps1/src/cpu/).
Cave НЕ делаем (SH-4). В меню есть пункт "FB Neo (Arcade)" (общий корень /roms/fbneo),
но драйверов в прошивке там только 2 (batrider, bgaregga); остальные 373 сета —
чужие платы, каталог: docs/FBNEO-ROMS.md.

ЖЕЛЕЗО-ФАКТ: HDMI-панель стоит ФИЗИЧЕСКИ ПОРТРЕТНО (повёрнута на 90°).
Эффективный экран портретной панели = 600×1024. Буфер HDMI при этом 1024×600,
DE2 настроен слоем 1:1 (GSU-масштабирование НЕ используется).

РЕНДЕР (h3_bare/cores/cps1_host.cpp, host_render_frame, r0.363) — НЕ ЛОМАТЬ БЕЗ НУЖДЫ:
- Для ВСЕХ нормальных игр (CPS/NEO/Toaplan-горизонт и все остальные):
  «вписать по родному разрешению» — один равномерный коэффициент на обе оси
  (min(1024/W, 600/H)), центр всегда (511,299) в альбомных 1024×600, поля чёрные,
  ничего не режется и не искажается.
- Только для ПОРТРЕТНЫХ игр (Toaplan GP9001 с BDF_ORIENTATION_VERTICAL,
  truxton2 и т.п.): g_rot=1 — транспонированная запись в 600×1024 (по центру
  панели), равномерный масштаб ×2.5 -> 600×800. Обычные игры НЕ ДОЛЖНЫ этим
  затрагиваться (условие `g_rot = (gp9001 && vert) ? 1 : 0`).
- ВАЖНО про производительность: масштаб/поворот построены на 16.16 аккумуляторах
  и таблицах шага. НИКОГДА не вставлять деление/умножение int64 в пиксельный
  цикл (было «все аркады стали лагать» из-за ((int64)dx*cols)/vw на каждый пиксель
  — 64-битное деление на Cortex-A7 это софт-функция ~100+ тактов, 600k раз/кадр).

ОТКРЫТЫЕ ХВОСТЫ (в порядке приоритета):
1. Toaplan alcon/Slap Fight (M6805, plat "Miscellaneous"): заходит, самолёт
   управляется, но волны/враги не спавнятся («летаю по пустому»). В логе есть
   DBG-строка с hs=mcu_sent/main_sent,from_main/from_mcu — нужен её анализ на
   железе (жив ли handshake с протектором M6805 → если hs не двигается, чинить
   m6805 sync/taito_m68705).
2. Клавиатура: отложена. I8 Pro (Low-Speed 0603:0002) молчит и при удержании,
   и при отпускании; удержание на нём не работает, ESC-выход сделан x3;
   используют тишина-детект 40мс и событийный слой (usb_kbd.c). Другую работу
   по OHCI interrupt-IN (кольца TD/DONE) не продолжать без отладки на железе.
3. DBG-TEMP в cps1_host.cpp: печать `DBG ... pc= sek= zet= mcu= hs=` каждые 120
   кадров и `RND ... nz=` каждые 600 (только для Toaplan) — НЕ удалять до закрытия
   пункта 1, потом снять одним коммитом.
4. Toaplan детали: gp9001 горизонт показываем 304 (16 px правый overscan);
   «полосу из одной строки» справа больше нет. Если трогаешь — сверяйся с
   docs/NEOGEO-HANDOFF.md (правила по .h/чистым пересборкам).
