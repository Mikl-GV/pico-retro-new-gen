### 1.2. r735 — верифицированные баги ядер

1. **srtc.c:277 (SNES S-RTC)** — `if ((rtc.index >= 0) || (rtc.index < MAX_RTC_INDEX))` — **всегда истинно**.
   - Симптом: после 13-го загруженного байта RTC (`index == 13`) следующий байт от игры делает `rtc.data[13]` — **запись за массив** (структура `data[MAX_RTC_INDEX+1]` = 13 элементов; соседние поля `index/mode/timestamp` портятся). Игра: Dai Kaijyu Monogatari II.
   - Фикс: `&&`.

2. **c4emu.c:198 (SNES C4, MegamanX2/X3/SF2)** — `memset(C4RAM, 0, (w + row_padding/4)*h/2)`.
   - `C4RAM = &FillRAM[0x6000]` (буфер до 0x8000, лимит 0x2000). `w,h` — из регистров 0x1f89/0x1f8c (`& ~7`, до 0xF8). `(0xF8+16)*0xF8/2 ≈ 0x7A10 > 0x2000` — **запись за C4RAM в соседние структуры Memory**.
   - Фикс: кламп размера к 0x2000.

3. **pce_fast/psg.c:306 (PCE)** — `ch = &psg->channel[psg->select]` вычислялся **до** проверки `select > 5` в case 0x02..0x07.
   - Симптом: при невалидном `select` (битый/хомбрю-картридж) — разыменование за `channel[6]` (UB) на каждой записи в PSG.
   - Фикс: присваивание `ch` перенесено внутрь каждого case после guard'а.

4. **a5200/pokeysnd.c:1304 (`pokeysnd_process_16`)** — in-place конверсия 8→16 в том же буфере.
   - Механизм: `pokeysnd_process_8(buffer, sndn)` пишет байты в `buffer`, затем `buffer[i] = smp` (short) переписывает те же адреса. Чтение `((UBYTE*)buffer)[i]` для **чётных** `i` уже перезаписано short'ом меньшего индекса — **половина сэмплов искажена** (звук A5200 «грязный»).
   - Фикс: генерация во временный `tmp[2048]`, конверсия из неповреждённых байтов.

5. **gp_cheats.c:179, 222-235 (GPGX GG-8)** — для 8-bit Game Genie `p->old = compare`.
   - Симптом: при `compare == 0` патч ставился без проверки, а `unapply_rom_cheat` восстанавливал **0 вместо оригинала** — после снятия чита ROM оставался модифицированным.
   - Фикс: сохранение оригинального байта в `orig`/`has_orig` при первом применении, восстановление оригинала.

### 1.3. r735 — «недописанные» функции: звук не был подключён к I2S

Ключевая находка: несколько систем имеют статус READY, но **звук физически не уходил в I2S** (заглушки/пустые колбэки), хотя ядра синтезировали сэмплы.

| Система | Файл | Что было | Что стало |
|---|---|---|---|
| **MSX** | `msx/host/msx_host.c:124` | `WriteAudio()` — заглушка (`return Length`); PSG/YM2413 синтез шёл в ядре (`RenderAndPlayAudio`), но сэмплы выбрасывались | моно 48к → `i2s_push_sample` |
| **Vectrex** | `vecx_host.c:174` | `vecx_snd_push()` — заглушка; PSG (`vecx_psg_exec`, ~187.5 кГц) + DAC писали в буферы, но не выводились | PSG+DAC микс, ресемпл 187.5к→48к → I2S |
| **BK-0010** | `bk_host.c:160-161` | `host_audio_sample/batch` — заглушки; ядро шлёт `audio_batch_cb(zero_samples,…)` (тишина) | audio_cb → ресемпл 44.1к→48к → I2S |
| **МС1504** | `ms1504/ms1504_shim.c`, `ms1504_host.c` | `speakergensample()` — заглушка; fake86 `audio.c` **не в MS1504_BONES** (не собирается); PC-спикер не выводился | генерация квадрата по PIT ch2 в shim (`m15_tick_audio`), чтение host'ом → I2S |

Примечание по МС1504: `audio.c`/`timing.c` из fake86 не входят в сборку (заменены shim-заглушками), поэтому попытка подключить `tickaudio` из `audio.c` была бы мёртвым кодом — генератор перенесён в shim.

### 1.4. r735 — P1 (зависания/состояние CPU2)

6. **settings.c:758 (калибровка тача с TFT)** — `case 5` ждал `CAL_CMD == 1` **без таймаута** (в отличие от HDMI-пути `touch_cal_run`, где ~30 с).
   - Симптом: при не стартовавшем/зависшем CPU1 core0 висел навсегда (меню «мёртвое»).
   - Фикс: таймаут 300×100 мс с принудительным `CAL_CMD = 0`.

7. **emu.c:341 (выход по ESC×3)** — `i2s_ring_reset()` ставит CPU2 на PAUSE (r702, без auto-RESUME).
   - Симптом: после выхода по ESC×3 аудио-ядро оставалось в паузе до следующего `emu_prepare()` (фон меню молчал).
   - Фикс: явный `AUDIO_CMD_RESUME` после `i2s_ring_reset()`.

## 2. Проверено и отклонено (ложные срабатывания)

Эти кандидаты были проверены лично и **НЕ являются багами** (или не воспроизводятся на этом коде):

| Кандидат | Вердикт |
|---|---|
| MCUME пул `pool` переполняется (A9) | **Не подтверждён**: `theCart` не берётся из пула при наличии ROM (`theCart = rom`/`cart_small`); сумма выделений пула 36072 (4К+ игры) / 40168 (2K, ровно размер) — без переполнения |
| A7800 «дыры» в интерполяции строк (B2) | **Не подтверждён**: `y1(sy-1) == y0(sy)` — интерполяция непрерывна, все 240 строк покрываются |
| Vectrex `y_acc` «размазывает низ» | **Не подтверждён**: `if (nsy >= VX_H) nsy = VX_H - 1` — кламп есть |
| BK boot.c переполнение ROM-массива | **Не подтверждён**: BASIC 24K с 0xA000 до 0xFFFE — банки 2/3 (`rom[0]` + `system_rom`), в границах |
| ops.h макросы `A` (SHA/SYA/SXA/XAS) | **Не подтверждён**: опкоды 0x93/0x9F/0x9C/0x9E/0x9B не инстанцируются — x6502.c компилируется чисто (макросы вне switch) |
| FCEUMM `WaveFinal[2560]` vs `ssize` | **Не подтверждён**: SOUNDTS ~30000 → NeoFilterSound выдаёт ~780-800 сэмплов/кадр на 48к — 3× меньше буфера |
| C4 `outidx` в цикле scale/rotate | Требует живой проверки (диапазон при экстремальных w/h), кламп 0x2000 добавлен на memset |

## 5. Рекомендации

### Барьеры и атомарность (уже соблюдено)
- `PA_DAT` — единственный рантайм-писатель core0 (r706/r703); RMW неатомарны, но других писателей нет — сходится.
- Кольцо I2S: SPSC, `wr` только core0, `rd` только CPU2; `dmb` на публикации индекса и сэмплов — на месте.
- Почта cmd/seq/ack через uncached `.coherent` — согласовано.

### Что стоит сделать дальше (по приоритету)
1. **Дочитать нечитанные пласты** (TFT/HDMI, tft_drv.c, dw_hdmi.c, h3_lcd.c, оставшиеся boards) — в них возможны ещё «ключевые» баги.
2. **Стендовая проверка** подключённого звука MSX/Vectrex/BK/MS1504 (громкость/тон/шум) и калибровки тача, ESC×3.
3. **Fuse timer_sleep** — сброс `slept_ms` между сессиями.
4. **bk_host вертикальный масштаб** — решение владельца по композиции экрана.
5. **Схема питания/разводки** — не проверялась в этом заходе (нет схемы в репо).
