# План: вынос звука на CPU2 (Midway + Psikyo)

Документ для решения владельца. Ничего из описанного ещё не реализовано —
это проект работ, основанный на замерах r1669.

## 1. Факты (стенд r1669, `CPS: perf`)

Бюджет кадра: Midway — 54.7 Гц, 18.28 мс; Psikyo — 59.29 Гц, ~16.9 мс.
`render` (GSU/скейлер) и вывод — 2–3 мс, они не растут с нагрузкой.

| Игра | сцена | emu | run (TMS34010) | dcs (ADSP2100) | scan | snd | draw |
|---|---|---|---|---|---|---|---|
| MK1 | меню | 14.5 | 5.4 | 5.5 | 1.8 | 0.4 | 1.0 |
| MK1 | бой | 20.8 | 10.6 | 6.5 | 1.8 | 0.4 | 1.1 |
| MK2 | меню/бой | 37.6 | 10.5 | 23.2 | 1.8 | 0.0 | 1.0 |

Выводы:
- MK2 без выноса DCS не ускорить: 23 мс только на ADSP2100.
- MK1 в бою упирается в два слагаемых: `run` 10.6 (рост из-за gfx/PIXBLT)
  и `dcs` 6.5. Убери `dcs` — станет ~14 мс при бюджете 16.
- Звуковые провалы (`under`) — следствие недобора кадров, а не тракта.

Цифр по Psikyo в этой таблице нет: там звук синтезируется на core0
(YM2610 + YMF278B в одном миксе), профиля по фазам нет. Веха 0 — снять его.

## 2. Цель и критерии готовности

1. MK1, MK2, Psikyo-игры держат штатный темп (54.7 / 59.29 Гц) в бою.
2. `AUDIO-END ... under` = 0, звук без провалов и без задержки больше кадра.
3. Zero-регрессий: CPS-1/2, NEOGEO, SNES и прочие ядра не меняются.
4. `linkcheck: OK`, версия и `docs/` в синхроне, вехи записаны в HANDOVER.

## 3. Что именно переносим

**Midway (MK1/MK2).** На CPU2 уезжает пара «ADSP2100 + DCS2»
(`src/cpu/adsp2100/*`, `src/burn/drv/midway/dcs2k.cpp`) целиком: свой такт
(10 МГц), своя RAM, свои ROM. Core0 больше не зовёт `dcs_sound_sync()` в
слайс-цикле; он только пишет команды звуку в почту.

**Psikyo.** На CPU2 уезжает звуковой тракт целиком: Z80 (sound CPU) + YM2610
(FM/SSG/ADPCM-A/B) + YMF278B + микшер. Роль «моста» — регистры звуковых чипов:
core0 прокидывает в почту обращения к портам, CPU2 исполняет их в своём такте.

**Остаётся на core0:** TMS34010, gfx-операции, кадровый путь, DE2-скейлер.

## 4. Почему это даст темп

Слагаемые `emu` складываются в одном потоке. Снимаем `dcs`/`snd` с core0:

- MK1 в бою: 20.8 − 6.5 − 0.4 ≈ 13.9 мс < 16 → 54.7 fps с запасом.
- MK2: 37.6 − 23.2 ≈ 14.4 мс → 54.7 fps.
- Psikyo: снимается весь синтез, остаётся `run`+`render` (замер — веха 0).

Синтез уходит на CPU2, который сейчас только доливает TX FIFO I2S
(тысячи пар в секунду — нагрузка копеечная), то есть ядро свободно.

## 5. Устройство обмена

Опираемся на действующие правила проекта (`AGENTS.md`, `docs/MEMORY.md`):

- **Межъядерные данные — только SRAM A1**, не `.coherent` (кэш core0 её не
  видит у CPU2 без DCCMVAC). Занято: 0x94–0xC4 (счётчики, почта, cmd/ack),
  0x1000–0x8FFF звуковое кольцо. Свободно: 0x0–0x90 частично, 0x9000–0xBFFF.
- **Почта**: очевидная схема «команда + ack» по образцу `cmd/ack` (0xB8/0xBC):
  core0 кладёт пару (id, arg), поднимает счётчик; CPU2 читает, увеличивает
  `ack`. Кольцо команд на 64–256 записей в 0x9000.., чтобы не блокировать
  core0 при пачке регистровых записей.
- **Звук**: CPU2 сам пишет готовые сэмплы в кольцо (0x1000/0x5000) и сам
  доливает FIFO — `i2s_poll_fill()` остаётся единственным писателем TX FIFO
  (правило 11 проекта). Core0 кольцо больше не пишет.
- **Запуск/пауза**: `ready` (0x94), `pause` (0xA4), `active` (0xA8) уже есть —
  добавляем только признак «звук взял игру» (сброс при смене игры).

## 6. Этапы

**Веха 0. Профиль Psikyo.** Тем же счётчиком, что у Midway: `run`/`scan`/
`snd`/`draw` в `cps1_host.cpp`. Даёт бюджет и показывает, что именно
переносить (чистый синтез или ещё Z80). Стенд: 3–5 минут в игре.
*Выход: строка perf для s1945/gunbird, решение о границе переноса.*

**Веха 1. Почта и каркас.** Кольцо команд в SRAM A1, `cmd/ack`, обработчик
на CPU2, сброс при старте игры. Пока без переноса звука: CPU2 забирает
команды и молча их считает. Стенд: счётчики команд совпадают, регрессий нет.

**Веха 2. Midway: ADSP2100 + DCS2 на CPU2.**
- RAM/ROM звука — в DRAM, доступны CPU2 по физическим адресам.
- `TUnitSoundRead/Write` (0x01d0xxxx) и `TUnitSoundStateRead` — через почту.
- Темп: CPU2 эмулирует ADSP2100 по своим 10 МГц, независимо от слайсов;
  события звука получают метку цикла TMS34010, чтобы порядок команд сохранялся.
- Синтез DCS пишет прямо в кольцо.
*Проверка: MK1/MK2 — 54.7 fps, `dcs` у core0 ≈ 0, `under` = 0, звук без
задержки больше кадра; регистры/музыка на месте.*

**Веха 3. Psikyo: Z80+YM2610+YMF278B на CPU2.** Всё по той же почте; данные
ROM читает CPU2. Микшер и мягкий лимитер (`BURN_SND_SOFT`, r1655) переносятся
как есть.
*Проверка: s1945/gunbird/tengai — 59.29 fps, `under` = 0.*

**Веха 4. Уборка.** Убрать временный профиль, обновить `docs/MEMORY.md`
(карта почты), `docs/VENDOR.md` (что переделано), HANDOVER.

Каждая веха — отдельная прошивка со своей версией и проверкой на стенде.
Откат любой вехи — возврат вызова на core0 (флаг в SRAM), без ломки хоста.

## 7. Риски и как их ловим

| Риск | Что делаем |
|---|---|
| Гонки в почте (потеря команд) | кольцо с `produce/consume`, счётчики только CPU2 увеличивает; core0 ждёт при переполнении |
| Рассинхрон DCS и TMS34010 | метка цикла TMS34010 в команде; CPU2 догоняет по метке, а не по кадрам |
| Адресация DRAM с CPU2 (нет MMU) | звуковые буферы — в заранее отведённой физической зоне, адреса из `docs/MEMORY.md` |
| Дублирование `i2s_poll_fill` | TX FIFO пишет только CPU2 (правило 11) |
| Регрессия незвуковых ядер | правки только в периферии Midway/Psikyo + `i2s.c`/`cpu2`; сборка и стенд по списку |
| Латентность звука | не больше одного кадра; если больше — увеличить кольцо команд, а не темп |
